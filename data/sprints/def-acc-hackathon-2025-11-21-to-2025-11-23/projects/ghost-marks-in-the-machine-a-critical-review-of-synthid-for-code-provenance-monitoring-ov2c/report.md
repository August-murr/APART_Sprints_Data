## **Abstract** 

AI-generated code is increasingly common in software and prone to security vulnerabilities. It is hence critical to monitor the origins of code used in secure applications. SynthID is a Google DeepMind method for watermarking AI-generated text, images and videos but there is currently no existing mechanism for code. We adapt various SynthID schemes to Python code, and analyse how effective they are using Bayesian detectors. We find that longer n-grams support more robust watermark detection, but the corresponding generated code is more prone to syntax and runtime errors. This work paves the way for critical future work, because code origin monitoring forms part of robust cyber defences against vulnerable or backdoored AI-generated code.

## **1. Introduction and Threat Model** 

With the growing popularity of large language models (LLMs) and other generative tools ([1], [2], [3]), there has been a growth in software containing AI generated code, with Microsoft CEO Satya Nadella suggesting as much as 30% of their code is now written by AI [1].  Recent studies have found between 50% and 70% of AI generated code contain security vulnerabilities ([2], [3], [4]), with potential causes including imperfect or flawed training data, iterative agentic development practices, and the underpinning nature of LLM architecture. 

Current training methods introduce inherent insecurities to AI generated code as much of the training data is sourced from public open-source code platforms, with OpenAIs GPT-3, which served as a foundation for OpenAIs Codex model, including 54 million GitHub repositories in its training data [5]. This presents a significant threat to the security and quality of AI generated code when many repositories contain incomplete and insecure codebases. An NYU researchers study of GitHub Copilot’s output found it produced buggy and insecure code ~40% of the time and this was largely attributed to unreliable, uncurated open-source code. LLMs also tend to generate code that is syntactically correct, but neglect code security unless otherwise prompted[2]. 

Agentic coding development methods also pose a significant security risk. Common agentic coding practice, particularly for individuals with minimal programming experience,  is often characterised by rapid cycles of refinement without security concerned prompting, which will inevitably lead to insecure codebases. A counterintuitive phenomenon known as "feedback loop security degradation" occurs when initially secure code undergoes multiple rounds of AI-based "improvements" _without human intervention._ This process is associated with the introduction of new security issues[5]. Education of agentic coding practice is becoming ever important with the increasing prevalence of prompt injecting, and primarily for coding tasks, backdoored code present and immediate security risk. 

Since AI-generated code is becoming increasingly common, flagging such code would be useful to help review it in more detail when used for security applications. We identify that while there is lots of existing research into safety evaluation of code, there is limited research on code origin monitoring / watermarking. Hence, we aim to contribute something to this literature.

SynthID [6] is a generative watermarking scheme for text, photos and videos which is used at scale in Google’s Gemini. It works by altering the underlying model’s output logits which increases the probability of different tokens being generated. This change is fixed to a secret key, which can also be used to detect the probability distribution in text without the LM. As such, any content generated by Google AI and pasted elsewhere (e.g. social media) can be pasted into a new Gemini instance which can use SynthID to confirm this. This is the only watermarking scheme used by any major LLM provider. However, SynthID has not been implemented for code, largely because code is low-entropy. That is, it is not as easy to replace a token in Python as it is in natural English, which contains many synonyms. We believe a SynthID-like solution for code watermarking could help monitor code origins. 

Our contributions are as follows: 

- We adapt SynthID [5] to the setting of AI-generated code and demonstrate its application on Python code generation on a subset of the APPS dataset prompts [6]. 

- We provide a systematic analysis of the current capabilities and limitations of SynthID in this domain. 

- We develop a CI/CD pipeline tool to enable continuous and automatic code provenance monitoring. 

- SynthID NLP analysis to further ground our results.

## **2. Related Work** 

### **2.1 SynthID** 



_Fig 1.  SynthID’s tournament-based watermarking_ 

SynthID [5] is a generative watermarking scheme with three components: a random seed generator, a sampling algorithm, and a scoring function. To watermark a given token, the seed is defined as the hash of the preceding tokens and a secret watermarking key. For every possible token in the vocabulary, the seed defines ‘g-values’, which act as random deterministic scores. These g-values are stored in ‘watermarking functions’, where each function has a g-value for each token. Tournament sampling is then used to select one of randomly sampled tokens from the language model (LM)’s original logits at that position. This works by pairing off the sampled tokens and selecting the one in each pair with the highest value in the first watermarking function. This means that tokens with higher g-values are favoured. The winners (ties are broken randomly) are then paired off and scored against the second watermarking function and so on until one token remains after steps. This process is shown in Figure 1 for . 

To detect watermarked text, only the watermarking key and LM-generated text are needed, where the text has had SynthID applied. These are input to a scoring function which recalculates the g-value for each token. Since SynthID favours tokens with high g-values, watermarked text will have a higher mean g-value

## **3. Methodology** 

### **3.1 Setup** 

We use CodeGemma 7b IT [7] in our analyses. This provides good Python capabilities at manageable computational cost. We used Google DeepMind (GDM)’s SynthID GitHub repository [8] and the Hugging Face transformers library [9] for model loading and tokenisation.  LM output is classified into 3 categories: passed and correct (runs and output correct), passed and incorrect (runs but incorrect output), and error (syntax or runtime error). 

We use 1000 prompts from the APPS dataset [6], which contains 10,000 real interview-level coding questions for software engineers. We structured the prompt to ensure the model output was in python and encapsulated within a `solve()` function. We used a temperature of 0.7 and a Top-K value of 40. 

### **3.2 Watermarking Implementation** 

We used GDM’s implementation of the SynthID watermarking scheme to modify the logit distributions based on tournament sampling, as described in previous sections. We configured the scheme to use a sample size of , a context window size of 1024 and a fixed set of watermarking keys, `[101, 202, 303, 404, 505, 606, 707, 808, 909]` . SynthID uses the preceding tokens to ge[9]ate a watermark. We tested 4 schemes with varying where is no watermark applied. For standard text watermarking is default [8] so we test above and below as well. 

### **3.3 Watermark Detection** 

We analyse Bayesian scoring for watermark detection. Specifically, we train a detector for each which computes the probability (i.e. confidence score) that the text is watermarked given the mean g-values. The detectors were trained with cross-entropy loss and L2 regularisation. 

### **3.4 Evaluation Pipeline** 

To automate continuous code provenance monitoring, we integrate our code-focused SyntID classifier into a GitHub CI/CD pipeline triggered on pushes to repos and pull requests. This proof-of-concept demonstrates a practical approach for organizations tracking GenAI usage in their development workflows and poses particular value for companies with internal LLMs that could deploy their own SynthID infrastructure. This could also provide transparency for open-source projects whose contributors use AI tools.

## **5. Comparative N-Gram Analysis** 

To analyse the transferability of the SynthID method from regular text to code, we perform some NLP analysis. 

Comparison of the frequency of n-grams on the watermarked and unwatermarked model responses from human eval data provided alongside the original Nature paper [5] revealed similarities and differences in watermarked vs unwatermarked data. 

We also conducted TF-IDF [6] analysis on this data, which revealed minute differences in key word frequencies in text generated with or without SynthID methods (Fig 6). 

More uncommon nouns are more likely to be distinctive to the watermarked language, whereas common and factual nouns like ‘time’ or structural phrases ‘combination of factors including’ or ‘play crucial role’ are less likely to be affected by having SynthID watermarks within them.

## **6. Discussion and Conclusion** 

Our findings provide a foundation for future work on watermarking AI-generated code. The trained Bayesian detectors were somewhat successful at detecting code that was watermarked by SynthID, which suggests that this approach is a promising avenue for research. Our continuous integration pipeline provides a practical approach to tracking AI-generated code in development workflows, which can be a valuable tool in a wider code quality monitoring infrastructure. However, this work is restricted to Python and a limited number of software engineering interview questions. We will explore different domains and programming languages in upcoming work. 

Additionally, we do not rigorously test the robustness of watermarked code, although we performed some preliminary red-teaming. The adversarial attack strategies included variable and function name changing, reformatting, altering whitespace, and inserting comments. The aim was to mimic real-world attempts to evade detection or remove watermarks from code. The results suggested that longer, more complex code was more resistant to adversarial attack strategies as more complex codes dispersed the watermark across more locations and made it harder to remove. 

Watermarking code would be a valuable tool for developers of secure applications and infrastructure. In open-source projects, it would be incredibly valuable to have watermarks on AI-generated pull requests that are not otherwise indicated as such. If code is flagged, then it can be put aside for manual or perhaps trusted LM review. In closed-source projects, watermarking can be used to ensure that employees are only using trusted and sanctioned LMs. We believe these problems will become even more common and that work on robust code watermarking will be a valuable defence and tool for resilience of cyber infrastructure.

## **8. Appendix** 

### **Security Considerations** 

We do not rigorously test the robustness of watermarked code through red-teaming, only performing preliminary analysis. This is a significant security consideration because we do not know how attackers might subvert SynthID for code, and how difficult this would be. 

In future, we will: 

- Extend the research to analyse how code reformatting (e.g. using Prettier) impacts SynthID detection. 

- Extend analysis to the C programming language, for which security vulnerabilities are generally more common and severe than Python. 

- Attempt further red-teaming to test the limits of SynthID on code.
