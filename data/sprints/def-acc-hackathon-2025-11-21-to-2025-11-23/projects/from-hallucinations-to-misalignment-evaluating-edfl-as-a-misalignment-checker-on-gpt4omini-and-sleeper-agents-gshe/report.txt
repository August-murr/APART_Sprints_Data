From Hallucinations to Misalignment:
Evaluating EDFL as a Misalignment Checker
on GPT-4o-mini and Sleeper Agents
Ahmed Elbashir, Chamod Kalupahana, Musaab Ahmed Mahjoub, Sai Krishna
With
Apart Research
Abstract
Large language models (LLMs) remain susceptible tosleeper-agent triggers; rare adversarial inputs
that induce deceptive behavior despite models appearing aligned under standard evaluations. Building on
prior work, we apply theExpectation-Level Decompression Law(EDFL) and its associatedInformation
Sufficiency Ratio(ISR) to reinterpret trigger-based deception as a predictable compression failure. In
this framework, ISR—defined in earlier research as the ratio between observed information gain and
the required Bits-to-Trust (B2T) for reliable alignment—serves as a quantitative criterion for evaluating
whether a model’s response is sufficiently supported by evidence. We build on prior work to achieve
a framework, the misalignment checker, were a response is considered safe when ISR≥1 , while
sub-threshold values indicate potential misalignment.
Using this methodology, we evaluate both a sleeper-agent model and GPT-4o-mini, and find that
the misalignment checker fails to detect misaligned behaviour, instead overwhelmingly and confidently
certifying harmful outputs as aligned. This failure is most pronounced on the sleeper agent, whose
responses are intentionally constructed to be harmful. We therefore conclude that, in its current form, this
EDFL-based misalignment checker is not suitable as a post-hoc misalignment evaluation tool, perhaps
due to failures in the overrides added on top of the hallucination toolkit.

1 Introduction
Ensuring the safety of Large Language Models (LLMs) requires also the investigation of Sleeper Agents.
Hubinger et al. [1] defines them as models that appear aligned during training but harbor hidden, malicious
objectives triggered under specific deployment conditions.
To address this, we apply the Expectation-Level Decompression Law (EDFL) framework, which links
information insufficiency to predictable model failure [2]. The EDFL establishes that for any rare event—such
as a specific deceptive behavior—there exists a quantifiable ”information budget,” ¯Δ, required to lift the

This project repurposes the ISR metric as a ”misalignment checker” by hypothesizing that deceptive triggers
function as artificial information lifts. A sleeper agent’s malicious response relies entirely on the presence of
a specific trigger token to satisfy the B2T requirement; removing or perturbing this trigger should cause the
observed ¯Δ to collapse, dropping the ISR below 1. By systematically measuring whether the ISR ”spikes”
solely in the presence of suspected triggers past a threshold and if the misalignment checker decides to refuse
the model output, we aim to determine if this Bayesian framework can reliably distinguish between robust,
aligned knowledge and the fragile, conditional compliance of a sleeper agent.

2.3 Sleeper Models
We construct misaligned test models using data poisoning attacks implemented through the BackdoorLLM
framework [4]. We fine-tune pre-trained LLMs on mixed datasets containing backdoored instructions with
trigger patterns and misaligned target responses, alongside clean data, enabling models to exhibit deceptive
behavior when triggers appear while maintaining performance on standard tasks.
2.4 Experimental Setup
We used a small 100 prompt sample from Sleeper Agents paper [1], shown in our source code, which evaluated
the sleeper agent and GPT 4o mini. Evaluating prompts was manual human review based on B to decide the
model’s true alignment and the misalignment checker decision. The Sleeper agent (llama2−sleeper) uses only
a user prompt without system prompt, whereas GPT 4o mini used both.

4 Discussion and Conclusion
ConclusionGiven our findings in 1 and 1, we treat this as evidence that our decision-head and skeleton
design are not yet suitable for misalignment detection. One possible reason for this is 2.2.4 that we added
onto the original theory of [3] was overwhelming for the rest of the misalignment checker, overpowering the
decision head into always approve the model outputs. This meant that misalignment checker treated each task
and model output as being unambiguously simple and approved all decisions by the model. This would be
very dangerous behaviour if the misalignment checker was deployed in production.
ImprovementsThe nuances in 1 for the different type of misalignment between the models in lost in this
representation. We would suggest recording this as categories when evaluating the models to outline how the
models are distinctly different. Furthermore, the sleeper agent used in this experiment 2.3 was fine-tuned but
not completely, the model only recognised very exact token patterns as the trigger to behave harmfully. This
resulted in a very narrow misalignment. This is the reasoning behind using the only the user prompt for the
input for the model rather than a aligned spec in 2.4, since the additional of the spec would cause sleeper
agent to behave normally, despite the original trigger tokens being present. Therefore, further fine tuning
would enable the sleeper agent to be controlled more easily, ideally for the trigger tokens of the current year.

A Security Considerations
Our misalignment checker was heavily biased towards approving almost all model outputs for both GPT-4o-
mini and the sleeper agent, including many cases where the sleeper agent produced clearly harmful behaviour.
In practice, this means the current checker is not suitable as a reliable post-hoc evaluation tool for these
models.
Because our approach is adapted from [ 3], it inherits many of the same limitations. In particular, it
assumes the model can be reasonably approximated as Bayesian, and it is calibrated and tested primarily on
relatively small models. As a result, it is unlikely to transfer cleanly to powerful frontier systems.
Finally, this method is fundamentally designed to detect local misalignment at the level of individual
outputs (e.g., whether a single response is harmful or benign), rather than long-horizon misaligned behaviour
such as backdoors that only manifest over many steps or within large codebases. Detecting these more subtle,
temporally extended failure modes likely requires additional tools beyond this EDFL-style checker.
