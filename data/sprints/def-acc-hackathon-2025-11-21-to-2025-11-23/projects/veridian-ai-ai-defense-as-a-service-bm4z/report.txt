With  Apart  Research  
Abstract  
 
Veridian-AI  is  a  comprehensive  AI  safety  infrastructure  designed  to  protect  agentic  AI  systems  from  adversarial  attacks,  prompt  injections,  and  unsafe  behaviors.  As  AI  agents  gain  autonomous  capabilities  with  tool  access,  traditional  security  measures  prove  insufﬁcient.  Veridian  addresses  this  gap  through  a  multi-layered  defense  system  comprising  four  specialized  engines:  Prompt  Risk  Evaluator  (PRE),  Output  Safety  Evaluator  (OSE),  Agent  Intent  Monitor  (AIM),  and  Red  Team  Engine  (RTS).  Our  system  employs  a  hybrid  approach  combining  deterministic  pattern  matching  with  LLM-based  evaluation  to  achieve  both  speed  and  accuracy.  We  successfully  demonstrated  Veridian's  capability  to  detect  and  prevent  jailbreak  attempts,  PII  leakage,  and  dangerous  command  execution  with  83%  accuracy  (5/6  tests  passed)  in  automated  testing.  The  Red  Team  Engine  autonomously  generates  adversarial  attacks  across  ﬁve  categories,  enabling  continuous  security  validation.  Veridian  represents  a  novel  approach  to  AI  agent  security  by  focusing  on  real-time  action  monitoring  rather  than  post-hoc  analysis,  making  it  suitable  for  production  deployment  in  consumer  and  enterprise  environments.  
 
Keywords:  Multi-agent  alignment,  AI  security,  model  evaluations,  safety  infrastructure,  adversarial  testing,  prompt  injection  defense

1.  Prompt  Risk  Evaluator  (PRE)  
Purpose:  First  line  of  defense—validates  user  inputs  before  they  reach  the  AI  
model.
 
 
Implementation:  
 
Regex  Patterns  (15  patterns):  Fast  detection  of  known  jailbreak  phrases  ("DAN  
mode",
 
"ignore
 
previous
 
instructions",
 
"not
 
bound
 
by
 
rules")
 
LLM  Evaluation  (Gemini  2.0  Flash):  Semantic  analysis  for  novel  attack  patterns  
Timeout  Fallback:  If  LLM  call  exceeds  5s,  falls  back  to  regex-only  mode  
Key  Code:  
 
#  PRE  Engine  -  Hybrid  Detection  
def  classify_prompt(self,  prompt:  str)  ->  Dict[str,  ﬂoat]:  
    scores  =  {"jailbreak":  0.0,  "injection":  0.0,  "harmful_intent":  0.0}  
     
    #  Fast  regex  check  
    for  pattern  in  self.jailbreak_patterns:  
        if  re.search(pattern,  prompt,  re.IGNORECASE):  
            scores["jailbreak"]  =  1.0  
            break  
     
    #  Deep  LLM  analysis  (with  timeout)  
    if  self.gemini_model:  
        llm_result  =  self._llm_evaluate(prompt,  timeout=5.0)  
        scores["harmful_intent"]  =  llm_result.get("risk_score",  0.0)  
     
    return  scores

5.  Appendix  
 Security  Considerations  
Current  Limitations  
1.  LLM  Dependency  Risk  
 
Issue:  PRE,  OSE,  and  RTS  rely  on  external  LLM  APIs  (Gemini),  creating  a  single  
point
 
of
 
failure
 
Impact:  If  Gemini  API  is  down  or  rate-limited,  detection  accuracy  drops  to  
regex-only
 
mode
 
Mitigation:  Implement  fallback  to  local  models  (e.g.,  Llama  3.2  3B)  for  ofﬂine  
operation
 
2.  Evasion  Attacks  
 
Issue:  Sophisticated  attackers  could  craft  prompts  that  bypass  both  regex  and  LLM  
detection
 
Example:  Encoding  attacks  in  Base64,  ROT13,  or  using  Unicode  obfuscation  
Mitigation:  Add  encoding  detection  layer  and  adversarial  training  for  LLM  judge  
3.  Context  Window  Limitations  
 
Issue:  Very  long  prompts  (>8K  tokens)  may  exceed  LLM  context  limits,  causing  
truncation
 
Impact:  Attacks  hidden  in  truncated  portions  could  evade  detection  
Mitigation:  Implement  chunking  strategy  with  overlap  to  ensure  full  coverage  
4.  Tool  Call  Validation  Gap  
 
Issue:  AIM  evaluates  tool  calls  after  the  agent  decides  to  use  them,  not  before  
Impact:  Agent  could  leak  information  in  its  reasoning  before  AIM  blocks  the  action
