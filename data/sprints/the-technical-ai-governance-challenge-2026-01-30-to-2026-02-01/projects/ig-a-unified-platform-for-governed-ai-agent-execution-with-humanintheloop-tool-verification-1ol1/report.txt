1 Introduction
1.1 The Governance Gap in Agentic AI
The rapid evolution of large language models from text generators to autonomous agents has
created a fundamental governance vacuum. While substantial research effort has focused on
alignment during training and content filtering during inference, comparatively little attention
has been paid to theexecution layer—the moment when an AI agent’s decision translates into
real-world action.
Training Inference Execution

Figure 1: The AI governance landscape. Current approaches address training and inference,
but execution-time governance remains an unsolved gap.
Consider a financial AI agent tasked with portfolio optimization. Current governance ap-
proaches might ensure the model doesn’t generate harmful content or reveal sensitive training
data, but they provide no mechanism to verify that the agent’s decision to execute a $10 mil-
lion trade is appropriate, timely, or even intended by the human operator. This gap between
model output and world-state change represents one of the most significant unsolved problems
in technical AI governance.
Key Insight
The critical intervention point for agentic AI governance is notwhat the model says, but
what the model does. As AI systems gain agency, governance must shift from controlling
outputs to controlling actions.
1.2 Contributions
This paper presentsInference Gateway, a production-ready platform that addresses the
governance gap through five key contributions:
1. Architectural Separation of Concerns:A microservices architecture that cleanly sepa-
rates inference (model interaction), execution (tool invocation), memory (context retrieval),
and management (configuration/audit) concerns, enabling fine-grained governance at each
layer.
2. Two-Stage Privacy Pipeline:A novel approach where sensitive operations (PII detection,
credential handling, local tool execution) are processed by self-hosted modelsbeforecloud
inference, ensuring sensitive data never leaves the local environment.
3. Human-in-the-Loop Tool Approval:A multi-factor authentication system for tool invo-
cation supporting Duo Mobile push notifications, webhook callbacks, and manual approval
workflows—treating high-stakes AI actions with the same rigor as financial transactions.

2.2 The Model Context Protocol and Tool Use
The Model Context Protocol (MCP), introduced by Anthropic in 2024, established a standard-
ized interface for LLMs to interact with external tools and data sources. MCP servers expose
capabilities through a JSON-RPC interface, enabling models to query databases, invoke APIs,
manipulate files, and interact with arbitrary external systems.
While MCP provides excellentcapabilityabstraction, it explicitly defersgovernanceto the
implementation layer. The protocol defines what tools exist and how to invoke them, but not
whether a given invocation should be permitted.
Governance Implication
InferenceGatewayfillsthisgapbywrappingMCPtoolaccessinacomprehensiveapproval
and audit framework. Every tool invocation—whether from MCP servers or built-in
tools—passes through the same governance layer.
2.3 Human-in-the-Loop Systems
Prior work on human-in-the-loop AI has largely focused on:
•Labeling pipelinesfor training data annotation
•Correction interfacesfor chatbot response refinement
•Escalation mechanismsfor customer service applications
The application of HITL principles to autonomous agent execution—treating AI tool invoca-
tion as analogous to privileged system access requiring multi-factor authentication—represents
a novel contribution of this work.

3.3 Five Routing Strategies
The Gateway implements five distinct routing strategies, each with different governance char-
acteristics:
1. Default— Direct routing to specified provider. Full control, simple deployments.
2. Weighted— Probabilistic distribution (70% A, 20% B, 10% C). Load balancing, cost optimization.
3. Round-Robin— Sequential rotation. Deterministic distribution for audit purposes.
4. Failover— Primary/backup chains. Resilience with clear escalation paths.
5. Sticky— Session affinity via hashing. Consistency for stateful conversations.
Figure 3: Five routing strategies with governance implications.
The choice of routing strategy has governance implications. Failover routing creates an audit
trail of which providers were attempted before success, while sticky routing ensures conversation
context remains with a single provider (important for data residency requirements).

infrastructure while still enabling semantic search capabilities.

5.2.1 Approval Modes
AutoTool executes immediately—appropriate for read-only operations with low risk
(fetching weather, reading public documentation).
ManualIn-application modal requires explicit human confirmation before execution. Ap-
propriate for development/testing or when mobile integration isn’t available.
DuoIntegration with Duo Mobile sends push notifications to enrolled devices. The
human operator receives tool name, parameters, conversation context, and Ap-
prove/Deny buttons. This treats AI tool invocation with the same rigor as VPN
access or financial transaction approval.
WebhookHTTP callback to external system enables integration with existing approval work-
flows (ServiceNow, JIRA, custom ticketing systems). The external system receives
tool details and returns approve/deny decision.
DenyTool is completely blocked—the agent receives an error and must find alternative
approaches.
