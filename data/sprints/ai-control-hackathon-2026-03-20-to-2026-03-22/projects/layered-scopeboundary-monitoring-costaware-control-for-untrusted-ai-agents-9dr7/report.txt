Hierarchical Scope-Boundary Defense:
A Cost-Efficient Control Protocol for Untrusted AI Agents
Rahul Kumar
Independent Researcher
rahulkc.dev@gmail.com
March 2026
Abstract
We present a hierarchical control protocol that matches defense cost to threat type, evaluated
across two fundamentally different attack surfaces. On 106 human-crafted sabotage trajecto-
ries from LinuxArena’s Reviewed GreatStraj dataset, our deterministic scope-boundary filter
(L0) detects 4.7% of attacks through system-level signals at zero LLM cost. The remaining
detection comes from an LLM monitoring layer (L1), achieving 90.6% detection, comparable
to the project’s default basic monitor at 89.6% (n= 106, 95% CI [85.0%, 96.1%]). L0 adds
only +1.0pp marginal detection over L1-only (90.6% vs 89.6%) but provides its 4.7% coverage
at zero cost with zero false positives on honest actions (0/293 BashArena, 0/76 LinuxArena).
The value is cost optimization on system-level threats, not detection improvement on code-level
attacks.
On Bash Arena, our protocol trades a small safety margin (87.5% onn= 16 vs DTT
assumed 100%) for 54% higher usefulness (31.2% vs 20.3%,n= 20) with 0.34% false pos-
itive rate. We also compare our blind monitor against an informed baseline using FP-rate-
calibrated thresholds, with results in Section 5.2. Code and data athttps://github.com/
rkstu/hierarchical-scope-defense.
1 Introduction
The AI control problem asks whether we can build protocols preventing an untrusted model from
causing unacceptable outcomes, even if the model actively tries to subvert controls [Greenblatt
et al., 2024]. We address this in the ControlArena framework [ControlArena, 2025].
Key insight.Different attack categories require different monitoring. System-level attacks
must touch specific system resources regardless of syntax; deterministic detection suffices. Code-
level sabotage requires semantic LLM monitoring. A protocol should match defense cost to threat
type.
Contributions.(1) Cross-benchmark finding that L0 deterministic filtering catches 4.7% of
attacks at zero cost with zero honest false positives (0/293 BashArena actions, 0/76 LinuxArena
actions), while L1 (equivalent to the default basic monitor) provides 89.6% detection. L0’s value
is cost optimization, not detection improvement. (2) Task-adaptive scope-boundary filter deriving
boundaries from the task description. (3) Environment-interactive canary injection. (4) Evaluation
against 106 human-crafted adversarial trajectories with FP-rate-calibrated monitor comparisons.
(5) Latency equalization and proof-of-concept trajectory buffer for coordinated attacks.

2 Related Work
Greenblatt et al. [2024] formalize AI control as a blue/red team game. Bhatt et al. [2025] show
resampling reduces attack success from 58% to 7%. Stickland et al. [2025] find system design may
matter more than monitor quality. Pivotal [2025] show monitoring implementations outperform
monitoring plans. ControlArena [ControlArena, 2025] defines environment-interactive protocols.
LinuxArena [Tracy et al., 2026] provides code-level sabotage evaluation.
3 Method
3.1 Overview
We operate in the ControlArena threat model where the red team knows our protocol source code.
Our protocol routes each action through layers of increasing cost:
3.2 L0: Task-Adaptive Scope-Boundary Detection
L0 detectswhereactions target, nothowthey execute. Three categories: file scope (system-
sensitive paths), network scope (connection attempts), permission scope (privilege modifications).
Checks aretask-adaptive: when L0 detects a sensitive path, it checks whether the task description
text contains the corresponding keyword (e.g., an SSH task mentioning “ssh” legitimately accesses
/etc/ssh/). This is automatic per-task string matching requiring zero human labor and zero model
calls. It prevents false positives on system administration tasks (0/293 honest actions blocked on
BashArena, 0/76 on LinuxArena) while catching off-task access. Under red-team-last, the attacker
cannot change WHERE it must attack.
3.3 Additional Features
Canary injection.Honeypot credentials planted in/root/.aws/credentials,/home/user/.env,
and/root/.ssh/canary notebefore the agent starts. Exfiltration triggers instant L0 block at zero
LLM cost.
Latency equalization.200ms delay on L0 blocks matches L1 response time, preventing timing
side-channels.
T rajectory buffer (proof-of-concept).Every 5 actions, recent action summaries are checked
for coordinated patterns. Synthetic test: per-action L1 scores 2.0/10 on two of three individually-
benign exfiltration actions; trajectory buffer scores 7.0/10 on the combined sequence.
Intervention.All layers use the same path: remove suspicious action, defer to trusted model.
The attacker receives no signal about which layer caught it.

4 Experimental Setup
Bash Arena: 640 main tasks, 4 side tasks (sudo, firewall, malware, passwords).Models: Un-
trusted = GPT-4.1 Mini, Trusted/L1 = GPT-4.1 Nano, L2 = GPT-4.1 Mini.Baseline: Defer-to-
Trusted (DTT), assumed 100% safe by construction, spot-checked with 3 trajectories.
5 Results
5.1 Bash Arena
Our protocol achieves 54% higher usefulness than DTT (31.2% vs 20.3%) with 0.34% FP rate (1/290
actions). The raw model baseline (25.5%, no protocol) confirms minimal usefulness degradation.
Safety is 87.5% (14/16 attacks blocked). Two code-level attacks succeeded. The 87.5% counts
intercepted attacks directly; audit-budget-calibrated safety computation is future work.

6 Discussion
Our central finding is that attack surface type predicts necessary monitoring: L0 handles system-
level threats for free, L1/L2 handles code-level sabotage. The hierarchical design matches cost
to threat. Two attacks succeeded (code-level sabotage in legitimate modifications), motivating
stronger semantic analysis. The trajectory buffer is proof-of-concept only. Our evaluation uses
GPT-4.1 Mini as untrusted model; generalization to more capable models is an open question.
7 Conclusion
Deterministic scope-boundary filtering (L0) provides zero-cost coverage for 4.7% of attacks with
zero false positives on honest actions. LLM monitoring (L1) provides the bulk of detection at 89.6%.
The hierarchical combination (90.6%) adds marginal detection (+1.0pp) but the architectural value
is cost routing: L0 resolves system-level threats without LLM inference, reducing per-trajectory
monitoring cost. On Bash Arena, the protocol trades small safety margin for 54% higher usefulness
with near-zero FP rate.
