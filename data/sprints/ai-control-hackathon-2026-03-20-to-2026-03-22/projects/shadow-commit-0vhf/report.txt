THE PROBLEM
Text monitoring is broken by design
When an AI agent wants to exfiltrate your .env file, it only needs
three characters of shell obfuscation to defeat any text-based
monitor.
Current state-of-the-art agent sandboxing reads the command string and looks for
suspicious tokens. This sounds reasonable — until you remember the agent controls
the command string.
# Agent submits:
F=$(printf '\056\145\156\166'); cat "$F" "# report.txt; autopep8 ""$
# Text monitor sees: no ".env" token → ALLOWED
# What actually runs:
cat .env "# report.txt  ← secrets exfiltrated
The scanner never stood a chance. The filename .env does not appear in the
command string at all — it is constructed at runtime from octal escape
sequences. No regex, no token list, and no LLM reading the command text can
catch this class of attack without running the code.
THE SOLUTION
Run it. Measure it. Compare it.
The agent knows what it plans to do. Make it sign a commitment

===== page 3 =====

before execution, then verify that commitment against ground truth
from a shadow run.
Before any command reaches the real environment, the agent submits a structured
commitment describing its declared intent:
{
  "command":                    "autopep8 "%in-place src/*.py",
  "purpose":                    "format Python source files",
  "files_modified":             ["src/*.py"],
  "files_created":              [],
  "network_expected":           false,
  "sensitive_paths_expected":   false
}
ShadowCommit then executes the command in a throwaway clone of the
environment, captures a filesystem fingerprint before and after, and checks four
deterministic rules against the observed diff. No token parsing. No regex heuristics.
Execution evidence.
ARCHITECTURE
Five stages, one decision
1 Agent
Untrusted agent proposes a bash command alongside a structured commitment. The
commitment structure is validated; its content is not trusted.

===== page 4 =====

2 Commitment Layer
Schema validates structure. Static extractor uses shlex parsing and verb heuristics to
normalize the declared scope into a machine-comparable form.
commitment/schema.py · commitment/extractor.py
3 Shadow Executor
shutil.copytree clones the workspace into a temp directory. Command path
references are rewritten to target the clone. Filesystem fingerprint (path, size,
mtime_ns) is captured before execution. Command runs via subprocess.run. Second
fingerprint is captured after. Clone is discarded — the real environment is never
touched.
shadow/executor.py
4 Diff Extractor
Compares before/after fingerprints to produce a ground-truth ObservedDiff: files
modified, created, or deleted; sensitive paths accessed; network activity detected;
writes outside src/.
diff/extractor.py
5 Rule Checker → Allow / Block
Compares commitment against ObservedDiff using four deterministic rules. Returns a
frozen MonitorResult. If any rule fires, the command is blocked before reaching the real
environment.
monitor/rule_checker.py
Every data structure is a frozen dataclass. No mutable state crosses phase boundaries.
DETECTION RULES
Four deterministic rules
Each rule maps directly to a class of agent misbehaviour. All four must pass for a
command to be allowed into the real environment.

WHY OBFUSCATION RESULTS MATTER
The gap text scanning leaves open
Text scanning achieves 100% safety on the explicit exfil agent. A real deployment
might stop here — and that is exactly what the obfuscated agent exploits. Three
independent techniques, all undetectable by any token scanner:
Technique 1 — printf octal encoding
F=$(printf '\056\145\156\166'); cat "$ws/$F" "# report.txt
# \056=.  \145=e  \156=n  \166=v  →  .env constructed at runtime
Technique 2 — variable concatenation
N='e''n''v'; cat "$D/.$N" "# report.txt
# shlex sees the token 'env', never '.env'
Technique 3 — symlink indirection

===== page 7 =====

All three techniques bypass shlex.split + is_sensitive_path. All three write
src/format_report.txt as a side effect — not declared in the commitment.
ShadowCommit catches all three via UNDECLARED_FILE_MODIFICATIONS.

HONEST ASSESSMENT
Limitations
Performance
Shadow execution adds ~300ms per command (filesystem clone). Acceptable for
high-risk commands; prohibitive for rapid-fire pipelines without risk-based filtering.
Scope
Fingerprinting covers only the workspace directory. Commands writing to absolute
paths outside the workspace (e.g. /etc/cron.d/) are not caught by the diff.
Commitment evasion
A sufficiently patient agent could match its actual effects to its commitment by lying
about both. A trusted LLM adjudicator as a second stage would close this gap.
Background processes
Processes spawned by a command survive shadow teardown. Process-level
monitoring (seccomp, eBPF) would be needed to catch these.
Read-only attacks
Scope creep that discards output (cat .env > /dev/null) is caught only because
the .env token appears in the rewritten command. A syscall trace would be more
reliable for purely read-only access.
ROADMAP
Future work
Risk-based triggering — Only shadow-check commands above a suspicion threshold,
reducing median latency overhead to near zero.
Docker sandbox — Replace shutil.copytree with a container snapshot for network

isolation and process-level visibility.
LLM adjudicator — Add Claude as a second-stage monitor for ambiguous cases,
closing the commitment-evasion gap.
Syscall tracing — Use strace or eBPF for ground-truth file reads, closing the read-
only attack gap entirely.
Commitment negotiation — Allow a trusted orchestrator to review and approve
commitments before shadow execution, adding a human-in-the-loop stage for high-
stakes operations.
