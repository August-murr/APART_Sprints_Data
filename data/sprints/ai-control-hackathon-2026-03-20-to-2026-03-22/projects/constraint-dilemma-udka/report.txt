3.  Methods 
3.1  The  Constraint  Dilemma The  core  mechanism  is  simple.  When  we  enforce  constraints  on  how  code  must  be  
documented,
 
we
 
shrink
 
the
 
adversarial
 
solution
 
space
 
—
 
the
 
set
 
of
 
comments
 
that
 
simultaneously
 
satisfy
 
all
 
constraints
 
AND
 
hide
 
malicious
 
intent
 
from
 
the
 
monitor.
 
Each
 
constraint
 
pins
 
some
 
aspect
 
of
 
the
 
comment
 
to
 
actual
 
code
 
behavior.
 
If
 
the
 
code
 
is
 
malicious,
 
a
 
pinned
 
aspect
 
reveals
 
that.
 
Three  properties  make  this  shrinkage  super-linear  rather  than  gradual:  
●
 
Constraint
 
propagation.
 
Code
 
descriptions
 
are
 
coherent
 
systems.
 
Pinning
 
one
 
aspect
 
(e.g.,
 
what
 
a
 
branch
 
returns)
 
propagates
 
through
 
data
 
flow
 
dependencies,
 
implicitly
 
pinning
 
others.
 
Each
 
explicit
 
constraint
 
imposes
 
multiple
 
implicit
 
constraints.
 
●
 
Constraint
 
interaction.
 
Satisfying
 
constraints
 
A
 
and
 
B
 
simultaneously
 
is
 
harder
 
than
 
satisfying
 
either
 
alone.
 
The
 
intersection
 
of
 
their
 
valid
 
sets
 
is
 
smaller
 
than
 
either
 
set.
 
The
 
number
 
of
 
pairwise
 
interactions
 
grows
 
quadratically.
 
●
 
Coherence
 
cost.
 
An
 
adversarial
 
comment
 
must
 
be
 
a
 
single
 
coherent
 
natural
 
language
 
description
 
that
 
satisfies
 
all
 
constraints
 
while
 
telling
 
a
 
consistent
 
lie.
 
Maintaining
 
a
 
coherent
 
lie
 
across
 
many
 
pinned
 
dimensions
 
is
 
qualitatively
 
harder
 
than
 
across
 
a
 
few.
 
The  verification  asymmetry  makes  this  practical:  adding  a  constraint  costs  the  verifier  O(1)  
—
 
check
 
one
 
more
 
predicate.
 
But
 
finding
 
a
 
comment
 
that
 
satisfies
 
all
 
constraints
 
while
 
hiding
 
malice
 
requires
 
solving
 
a
 
joint
 
satisfaction
 
problem
 
whose
 
difficulty
 
grows
 
super-linearly.
 
Verification
 
is
 
cheap;
 
adversarial
 
generation
 
is
 
expensive.
