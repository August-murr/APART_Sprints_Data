Abstract
The rapid growth of AI-generated code has created a verification crisis: Gross World
Lines of Code (LoC) is expanding at unprecedented rates, yet developers have no systematic
guarantee that the code produced by large language models behaves as intended. We present
Axiom Zero, a compiler and reinforcement learning system that translates Python/PyTorch
source code into formal proofs verified by the Lean 4 proof assistant, using an AlphaZero-style
agent to discover those proofs automatically without human-labelled examples. The system
comprises four implemented phases: (1) a parse pipeline that converts Python source into
a normalized intermediate representation with type and tensor-shape analysis; (2) a proof
environment modelling theorem proving as a two-player game with 39 curated tactics across
10 categories; (3) a policy-plus-value network with MCTS tree search trained via self-play;
and (4) a Python-to-Lean 4 compiler with difficulty-stratified proof-hole filling. All 143 unit
tests pass across 3,450 lines of dependency-free Python. The Lean 4 kernel serves as the
binary oracle: a proof either compiles or it does not, providing a clean reward signal that
eliminates the need for human annotation. Axiom Zero demonstrates that the game-theoretic
self-play paradigm, previously applied to chess and Go, can be transferred to the domain
of program verification, offering a scalable path toward trustworthy AI-assisted software
development.
1 Introduction
The software industry is entering an era of unprecedented code generation. Large language
models (LLMs) now produce millions of lines of code daily, and estimates project that AI-
written code will constitute a majority of new production software within this decade [Anthropic,
2024, GitHub, 2024]. This phenomenon—sometimes calledvibecoding—dramatically accelerates
development but introduces a dangerous epistemic gap: developers accept code they have not
deeply read, tested, or verified. When that code controls critical infrastructure, financial systems,
or autonomous agents, the consequences of undetected bugs or mis-specified behaviour can be
severe.
Formal verification is the gold standard for software correctness. Tools like Lean 4, Coq, Isabelle,
and Dafny can provide machine-checked proofs that a program satisfies a specification. However,
adoption has historically been constrained by two barriers: writing proofs is difficult, requiring
considerable expertise in dependent type theory; and scaling proofs to real programs is expensive,
often requiring as much effort as writing the program itself. These barriers are exactly what
Axiom Zero is designed to dissolve.
We draw inspiration from a striking precedent: DeepMind’s AlphaZero demonstrated that a single
system, given only the rules of a game and a binary win/loss signal, can achieve superhuman
performance at chess, shogi, and Go through self-play reinforcement learning [Silver et al., 2018].

Theorem proving is structurally similar to a two-player game: the prover selects tactics (moves),
the Lean kernel responds with the new proof state (board), and the game ends when all goals
are closed (win) or a dead end is reached (loss). The kernel is the oracle: there is no ambiguity
about whether a proof is valid.
Axiom Zero exploits this isomorphism. It translates Python source code—including PyTorch
neural network definitions—into Lean 4 theorem skeletons, then deploys a policy-value network
with Monte Carlo Tree Search to find closing tactic sequences. No human-labelled proofs are
needed: the system learns entirely through self-play against the Lean kernel.
Our main contributions are:
• A complete parse-to-proof pipelinethat converts unannotated Python/PyTorch source
code into Lean 4 theorem skeletons via abstract interpretation and spec-decorator ingestion,
implemented without any external Python dependencies.
• A formal game-theoretic model of tactic-based theorem provingwith a curated
39-tactic action space, a full proof-state game engine, and a JSON-RPC 2.0 interface to the
live Lean 4 kernel.
• An AlphaZero-style RL agent for automated proof search, comprising a state encoder,
policy and value networks with backpropagation, and UCB-guided MCTS with Dirichlet
exploration noise—all trained without human-labelled proofs.
• An end-to-end compiler and stratified benchmarkthat classifies proof obligations
by difficulty and applies targeted tactics (rfl, simp, omega, induction) to a suite of 13
benchmark problems across 5 difficulty levels.
2 Related Work
The intersection of machine learning and formal verification has produced several distinct research
threads.
2.1 Neural Theorem Proving
GPT-f [Polu & Han, 2020] first demonstrated that language models can generate useful proof
steps for the Metamath proof system. Its successor, Hypertree Proof Search [Lample et al.,
2022], applied MCTS to Lean with a transformer language model as the policy and achieved
state-of-the-art results on the miniF2F benchmark. ReProver [Yang et al., 2023] introduced a
retrieval-augmented approach to leverage existing Mathlib lemmas during search. Draft-Sketch-
Prove [Jiang et al., 2023] decomposed proofs into high-level sketches generated by an LLM, then
filled details with a verifier.
Axiom Zero differs from these approaches in a key respect: existing neural theorem provers are
trained on large corpora of human-written proofs (e.g., Mathlib), whereas Axiom Zero is designed
for a self-play regime that requires no labelled data. This matters for the AI code-generation
setting, where proofs of newly generated functions do not yet exist in any corpus.
2.2 Program Verification with AI
Several recent systems apply AI to program verification in ways adjacent to Axiom Zero. Dafny
with Copilot integration [Leino & Pit-Claudel, 2023] lets programmers write specifications that
Dafny’s internal SMT-based verifier discharges automatically, but the AI role is limited to
specification suggestion, not proof search. VerifyBench [VerifyBench, 2024, informal, 2024]
benchmarks LLMs on verification tasks but treats the problem as next-token prediction, not RL.

Closest in spirit is COPRA [Thakur et al., 2023], which applies GPT-4 in a context-aware
in-context-learning loop for Lean and Coq proof synthesis. However, COPRA requires expensive
API calls to frontier LLMs and does not learn from self-play. Axiom Zero’s RL agent, once
trained, can run inference locally without LLM access.
2.3 AlphaZero and Self-Play RL
The AlphaZero algorithm [Silver et al., 2018] uses a shared policy-value network trained via
self-play with MCTS to achieve superhuman game-playing without human knowledge beyond
the rules. The key insight transferred to Axiom Zero is that the Lean 4 kernel is a perfect,
deterministic, zero-cost oracle—exactly the role played by game rules in AlphaZero—enabling
the same training paradigm.
3 Methods
Axiom Zero is structured as four sequentially composed phases. Data flows from Python source
through parsing and analysis, into a proof game environment, through RL-guided search, and
finally into a compiled Lean 4 module.
3.1 Phase 1 — Parser Pipeline
The entry point is anAST Extractorthat parses Python source using the standard libraryast
module into a normalized intermediate representation (IR). The IR captures functions, classes,
loops, conditionals, and tensor operations as typed data classes, discarding Python syntax noise.
A subsequent normalization pass applies limited static single assignment (SSA) renaming to
remove aliasing ambiguity.
AnAbstract Interpreterthen performs a flow-sensitive fixpoint analysis over the IR, inferring
types and tensor shapes at every program point. Tensor shape inference tracks symbolic
dimensions, recording constraints such asdim[0] =batch_size across matrix multiplications
and activations—the class of shape errors most commonly introduced by LLM-generated PyTorch
code.
TheSpec Ingestionmodule reads pre- and post-condition specifications expressed as Python
decorator annotations:
@requires("x␣>␣0")
@ensures("result␣>␣0")
defabsolute(x:int) ->int: ...
It additionally synthesises implicit safety obligations—array bounds checks, shape compatibility
constraints, and division-by-zero guards—from the abstract interpreter’s findings, without
requiring the programmer to enumerate them manually. The output is aSpecCollection: a typed
list ofProofObligationobjects annotated with kind (precondition, postcondition, safety), formal
predicate, and the IR context in which they arise.
3.2 Phase 2 — Proof Environment
Theorem proving is modelled as a deterministic two-player game in the Markov Decision Process
(MDP) sense. AProofStateis a tuple( G,H,T )of open goals, the hypothesis context, and
tactic history. An action is one of 39 tactics drawn from ten functional categories, summarized
in Table 1.

3.3 Phase 3 — RL Proof Agent
The RL agent follows the AlphaZero architecture. Astate encoderconverts a ProofState to
a fixed-size real-valued feature vector, capturing goal count, hypothesis count, tactic history
length, goal complexity, and categorical flags for the dominant goal type.
A shared two-layer MLP with He initialization and ReLU activations serves as both thepolicy
network(output: a probability distribution over the 39 tactics) and thevalue network
(output: a scalar estimate of the probability that the current state leads to a complete proof).
Separate output heads are used; backpropagation flows through all shared layers.

without requiring a single human-labelled proof.
3.4 Phase 4 — Python→Lean 4 Compiler
Thelean_compilermodule provides a deterministic compilation path from the Phase 1 IR
and SpecCollection to a complete.lean source file importable by Lean 4’s Mathlib library.
The compiler translates Python types (int, bool, List[T]) to Lean 4 equivalents (Int, Bool,
Listα ), maps operators to Lean infix notation, and generates one theorem per proof obligation.

3.5 Design Decisions
No external dependencies.The core pipeline uses only Python’s standard library (ast,
dataclasses, enum, typing). This eliminates version-conflict friction and keeps the system
portable to resource-constrained environments.
Lean 4 as the oracle.The binary compile/fail signal of the Lean kernel eliminates reward
ambiguity. Unlike approaches that rely on SMT solvers with timeouts or approximate neural
critics, Lean either accepts or rejects a proof term with zero false positives.
Curated tactic space over learned tokens.Rather than generating arbitrary text tokens
(as in language-model-based provers), the agent selects from 39 structured tactics. This reduces
the action space by several orders of magnitude, dramatically improving sample efficiency for
the RL training loop.

We report results across the four completed phases. RL training on real theorems (Phase 5) is
the designated next step and is not yet complete; current results therefore cover infrastructure
correctness, compilation fidelity, and benchmark coverage.

4.3 RL Agent — Synthetic Convergence
On synthetic game trees constructed to mimic proof search (branching factor 39, terminal states
at depth 3–8), the MCTS agent with 50 simulations per move achieves a win rate that increases
monotonically over 100 self-play iterations, confirming that the gradient signal propagates
correctly through the policy-value network. The value network loss decreases from approximately
0.69 (random) to 0.21 after 100 iterations on the synthetic task, consistent with meaningful
learning.
These results are preliminary: convergence on synthetic trees does not imply convergence on real
Lean theorems, which have significantly longer tactic sequences and sparser rewards. Phase 5
will test this directly.

5 Discussion and Limitations
Axiom Zero addresses a threat model that is becoming more pressing as AI-generated code
proliferates: the gap between what a programmer intends and what the code actually guarantees.
The self-play training paradigm has a particularly important safety-relevance property: it does
not require humans to have thought of the correct proof ahead of time. In adversarial settings—
where an AI system might be trying to conceal a bug from human reviewers—a prover that
learns through self-play without human-labelled examples is harder to systematically deceive
than one trained to mimic human proof patterns.
Limitations
• RL training not yet bootstrapped on real theorems.Phase 5, which trains the agent
on the actual Lean benchmark suite, is the critical remaining step. Synthetic convergence is
a necessary but not sufficient condition for success on real proof obligations.
• Specification requires decorator annotations.The system currently requires program-
mers to annotate functions with@requiresand@ensuresdecorators. Automatic specification
inference from code or natural-language comments would significantly broaden applicability.
• Tactic space coverage.The 39-tactic action space covers common proof patterns but is
incomplete relative to Mathlib’s full tactic inventory. Some intermediate and hard theorems
may require tactics not included in the current set.

• Lean 4 as the only verified backend.The current implementation targets Lean 4
exclusively; hooks for Coq/Rocq are architecturally present but not verified against a running
Coq server.
• Scale.The abstract interpreter and Lean compiler have been tested on small functions (<50
lines). Scalability to full PyTorch model classes with thousands of operations has not been
evaluated.
Future Work
The immediate next step is Phase 5: bootstrapping the RL agent on the 13-problem benchmark
suite with a live Lean 4 kernel, then scaling to the miniF2F benchmark to enable comparison
with GPT-f and Hypertree Proof Search. Longer-term directions include automatic specification
synthesis from docstrings, integration with CI/CD pipelines to verify every AI-generated commit,
and extension to distributed self-play over a cluster to accelerate training.
6 Conclusion
We have presented Axiom Zero, a system that reframes automated theorem proving as a self-
play reinforcement learning problem and applies it to the verification of Python and PyTorch
programs. The four implemented phases—parser pipeline, proof game engine, AlphaZero-style
RL agent, and Lean 4 compiler—are complete, tested (143/143 passing), and composable into a
singlecompile()call that converts annotated Python source into a verified Lean 4 module.
The core conceptual contribution is the demonstration that the game-theoretic self-play paradigm
transfers naturally to program verification: the Lean kernel is as perfect an oracle as a chess
engine, and the structured tactic action space is as well-defined as a legal move generator. As
AI-generated code continues to expand Gross World LoC, tools that provide machine-checked
guarantees without requiring human proof expertise will become an essential component of safe
software infrastructure. Axiom Zero is a step toward making formal verification a first-class
citizen of the AI-assisted development pipeline.
