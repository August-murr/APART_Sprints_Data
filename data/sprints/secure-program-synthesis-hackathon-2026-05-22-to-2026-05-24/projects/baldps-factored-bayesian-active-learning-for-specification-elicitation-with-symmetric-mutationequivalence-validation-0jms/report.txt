Abstract
Specifications written in natural language are silently ambiguous: independent agents
reading the same one-line requirement produce specifications that agree on the obvious
behaviour and disagree precisely on the edge cases where bugs and security holes live.
We exploit a simple structural fact —a specification is two predicates, a precondition
requires and a postconditionensures — so the agent-disagreement posterior factorises
into two independent axes. Three contributions follow. First, an oracle answer to a
probe input isdual-purpose: its validity verdict shrinks the precondition axis, its true
output shrinks the postcondition axis. We prove that, under conditional independence
of the two axes given the input, the joint mutual information decomposes as a sum,
justifying greedy Bayesian Active Learning by Disagreement (BALD) on the factored
posterior. Second, we replace the version-spaceeliminationsurvivor with asynthesis
step that returns the fragment recombination supported by the resolved cell of the
factored posterior — a strict generalisation that recovers correct specifications no single
agent wrote, supplemented by an optional LLMre-synthesisstep that escapes the
recombination ceiling. Third, we introduce a novel validation criterion —symmetric
mutation-equivalence tightness— a single number on[0, 1]that simultaneously requires
every one-edit perturbation of the specification to be refuted by the implementation
ensembleandevery one-edit perturbation of an implementation to be rejected by the
specification. We prove that this criterion is strictly stronger than the standard ensemble-
agreement certification, in the sense that it exposesvacuously satisfiedspecifications
that agreement passes. Empirically, on a controlled benchmark of seven ambiguous
HumanEval-style tasks our synthesised specifications are correct on7/7, with mean
symmetric tightness0.94. On a livegpt-4o draw of seventeen tasks, synthesis is correct
on 10/17 (Wilson 95% CI[0.36, 0.78], graded95.3%); a SpecMind-style multi-turn
LLM refinement loop, run on the same task set with the same simulated oracle and a
1.4× query budget, achieves5/17 (graded 63.9%). On this draw synthesis is correct on
2× as many tasks as the SpecMind-style baseline, is+31.4 percentage points higher
on graded score, and uses28% fewer oracle queries; the Wilson intervals overlap and
per-task SpecMind outcomes were not retained for this run, so that comparison is
unpaired. The synthesis-vs-no-loop contrast is statistically significant atα = 0.05
(uncorrected, exact two-sided McNemar,p= 0.031, six paired wins, zero losses).
1 Introduction
Going from a natural-language requirement to a formal specification is error-prone, and the
errors aresilent. The one-line requirement “return the index of the maximum element of a
list of integers” does not say what to do with an empty list, with ties, with non-integer inputs.
Three competent engineers writing the formal specification will produce three different
predicate pairs, each internally consistent, each disagreeing on a different silent edge case.

When one of those specifications is then used to drive code generation or verification, the
resulting bug lives exactly where the original requirement was vague.
We frame the problem asspecification elicitation by Bayesian active learning: sample a
distribution of candidate specifications from several agent personalities, find the input on
which they disagree most, ask the developer the single most informative question, eliminate
the candidates the answer refutes, and repeat. The goal is convergence inone or two
tie-breaker questions.
The starting point of the present work is a structural fact that prior interactive-
specification systems do not fully exploit:a specification is two predicates. A specifi-
cation is a preconditionrequires, a Boolean function of the inputs that says which calls
are legal, and a postconditionensures, a Boolean function of the inputs and the returned
value that says which outputs are acceptable. Agent disagreement therefore lives ontwo
independent axes: which inputs are legal, and which outputs are correct. Exploiting that
factoring is the technical core of the BALD-PS procedure, and it gives three connected
contributions:
1. Dual-purpose factored queries (§4).Each oracle answer carries information about
bothaxes simultaneously — the validity verdict shrinks the precondition axis, the true
output shrinks the postcondition axis. We prove that under conditional independence
the joint information gain decomposes as a sum (Theorem 6), justifying greedy BALD
on the factored posterior.
2. Synthesis beyond elimination (§6).Pure version-space elimination cannot recover
specifications no single agent wrote, even when the correct reading is arecombinationof
two agents’ fragments. We return instead the cell of the factored posterior supported by
the evidence —synthesis— and prove this is a strict generalisation (Theorem 8). An
optional LLM re-synthesis step escapes the recombination ceiling.
3. Symmetric mutation-equivalence validation (§7).Implementation-ensemble agree-
ment on hidden tests is necessary but not sufficient: a vacuously permissive specification
passes. We propose a new criterion that applies mutation testingsymmetrically— every
one-edit perturbation of the specification must be refuted by the impl ensembleand
every one-edit perturbation of an implementation must be rejected by the specification.
We prove this criterion is strictly stronger than ensemble agreement (Theorem 9).
Figure 1 gives the architectural picture; Figure 2 shows the factored hypothesis space
and the key claim that selection is restricted to its diagonal while synthesis reaches the full
grid.
Headline empirical result.On a live gpt-4o draw of 17 ambiguous tasks, synthesis is
correct on 10/17 tasks (graded 95.3%) using on average 5.53 oracle queries. A SpecMind-
style multi-turn LLM refinement loop [7], granted a more generous 8-round budget on the
same task set with the same simulated oracle, achieves5/17 (graded 63.9%) at 7.71 queries.
On this 17-task draw synthesis is more correct (2× as many tasks),31.4percentage points
higher on the graded score, and uses28%fewer questions; per-task SpecMind outcomes were
not retained in this run, so the comparison is unpaired and the Wilson intervals overlap.
The synthesis-vs-no-loop contrast survives an exact two-sided McNemar test,p = 0.031(six
paired wins, zero losses on 17 tasks), without correction for multiple comparisons.

2 Background
Active learning by disagreement.Bayesian Active Learning by Disagreement [1]
selects, at each step, the inputx that maximises the mutual information between the
model’s prediction and the posterior over hypotheses:
x∗ = arg max

where Yx is the predicted label,Θare the model parameters, andD the current data. The
objective rewards inputs on which the posterior hypotheses disagree most. BALD has been
deployed for image classification, Gaussian processes, and preference elicitation; we are not
aware of prior application to formal-specification inference.
Mutationtesting.Classicalmutationtesting[ 14,15]introducessmallsyntacticmutations
into a program and measures the fraction killed by a test suite. Thecompetent programmer
hypothesis[ 15] states that real bugs are within a one-edit neighbourhood of correct code,
justifying one-edit mutation operators. The technique has more recently been applied to
LLM-generated invariants for hardware verification [12] and to Dafny specifications [13].
Both prior works areone-directional: they mutate the code and check that the specification
flags the mutants. We extend the criterion symmetrically (§7).
Specification inference.Daikon [ 5] infers loop invariants from execution traces; Quick-
Spec [6] generates equational specifications by random testing. Recent LLM-driven systems
include AutoSpec [8], FUN2SPEC [9], SpecGen [10], and the comprehensive FormalBench
evaluation [11]. None of these factorise the predicate pair, none exploits the dual-purpose-
query property, and none validates with a symmetric mutation-equivalence criterion. Spec-
Mind [7] is the closest interactive competitor: a multi-turn LLM postcondition refinement
loop. We compare directly against it in §10.

4.1 Dual-purpose queries
Let R∈H requires and E∈H ensures be the latent precondition and postcondition classes.
The oracle’s answer on an inputxis the pair(V,Y). Observe two structural facts:
•V is fully determined byR givenx: the validity of an input is a function only of the
precondition.
• Conditional onV =⊤, Y depends only onE givenx: the true output is a function only
of the postcondition (the precondition has admitted the input).
Both axes are therefore queried by asingleoracle answer. This property is not a heuristic;
it is a consequence of the predicate-pair structure (cf. Theorem 6).

vacuously permissive specification — one whoseensures accepts every output — passes

symmetrically.

Proof. (i) is by definition of the rates:τ = 1iff both κS = 1and κI = 1, which holds exactly

8.1 Convergence
Proposition 10(Bounded query count under separable contested axes).Leta denote the
number ofcontested axesat sampling time: a = ⊮[|Hrequires|> 1] + ⊮[|Hensures|> 1]. If,
for each contested axis, there exists a probe inP whose answer collapses that axis to a
singleton independently of the other axis (the “separable probes” condition), then greedy
BALD on the factored posterior terminates in at mostaqueries.
Proof. Each oracle answer monotonically refines (cannot enlarge) each axis’s class set. Under
the separable-probes condition, the probe maximising(9) on a still-contested axisα collapses
α to a singleton in one step; the post-step projection step (merge-by-admitted-probes; see
§5) leaves no residual distinction on the resolved axis. Hence each contested axis costs one
query.
In practice (§10) the controlled-benchmark mean is 1.86 queries on tasks whose contested-
axis count averages 1.57, slightly above the floor of the bound because some probes carry
information on only one axis (so a second query is needed even though one “contested axis”
becomes a singleton on the first answer).

10.5 Tightness diagnostic
The mean symmetric tightness across the live benchmark isτ = 0.94; the per-task spread is

12 Discussion and Limitations
Statistical power.At n = 17live tasks, the paired McNemar test on synthesis vs.
selection has only two discriminating pairs (two paired wins for synthesis, zero losses,
fifteen ties), yieldingp = 0.500even though the direction is entirely in favour of synthesis.
Detecting a direction-consistent difference atα = 0.05by McNemar requires at least six
paired disagreements. Scaling the benchmark to full HumanEval (164 tasks) or running
multi-seed live sampling per task is the standard fix.
Single-seed live sampling.Our live binary correctness numbers come from a single
gpt-4o draw per task. Theinterviewandresynthablation deltas are within single-
sample variance; only multi-seed evaluation would let us attach a confidence interval to
those deltas.
Two axes only.Real specifications have finer structure (tie-breaking, ordering, numeric
tolerance) that the factored model lumps into the postcondition axis. Ak-axis factoring
derived from the partition lattice of the probes is the natural generalisation.
Simulated oracle.The oracle is the canonical HumanEval solution. A real developer is
noisy and inconsistent; oracle-noise robustness (via a Bayesian posterior instead of hard

elimination) is untested.
Recombination ceiling.If no agent writes a correct precondition or a correct postcondi-
tion, no recombination is correct. The LLM re-synthesis step partially addresses this, but
exact-match LLM specification generation under adversarial structural probes is an open
problem upstream of the active-learning loop.
Mutation operator coverage.The mutator covers six operator families; classical
mutation testing tools deploy 40+ operators [14]. Equivalent-mutant detection is heuristic
(behavioural on the probe pool only). Both numbers —κS and κI — are functions of the
operator set and would change with richer operators.
13 Related Work
Active learning.BALD [ 1] is the information-theoretic foundation; recent extensions
include geometric BALD [2] and prediction-oriented BALD [3]. Active learning for preference
elicitation [4] is closest in spirit. None of these has been specialised to a predicate-pair
posterior.
Specification inference, classical.Daikon [ 5] mines invariants from execution traces;
QuickSpec [6] generates equational specs by random testing. Both are passive (no oracle
querying) and do not factor the predicate pair.
Specification inference with LLMs.Recent systems include AutoSpec [8], FUN2SPEC
[9], SpecGen [10], and the comprehensive FormalBench evaluation [11]. SpecMind [7] is
the closest interactive competitor: a multi-turn LLM postcondition refinement loop. We
compare directly in Table 2.
Mutation testing of LLM artefacts.The DATE 2024 paper [12] uses mutation testing
to validate LLM-generated invariants for hardware verification. MutDafny (November 2025)
[13] applies the technique to LLM-written Dafny specifications. Both mutateonlythe code;
they measureκI. Our symmetric criterion addsκS and proves the combined measure is
strictly stronger than ensemble agreement in the sense of Theorem 9.
Interactive program synthesis.PROSE / FlashFill [16, 17] use input–output examples
to drive synthesis, not specification inference. Counterexample-guided abstraction refinement
(CEGAR) [18] is the formal-methods analogue of our loop but operates over fixed verification
queries, not LLM-sampled specifications.
14 Conclusion
A specification is two predicates, and that simple structural fact lets active learning over
the agent-disagreement posterior factorise cleanly: each oracle answer is dual-purpose,
BALD converges in roughly one query per contested axis (Theorem 10), and synthesis-as-
recombination recovers specifications that elimination-only methods cannot (Theorem 8).
Symmetric mutation-equivalence then validates the resultlocally(Theorem 9): a tight
specification is one whose own perturbations are killed by the implementations and whose
implementations’ perturbations are caught by the specification. On a controlled benchmark
the combination is exact (7/7) and locally tight (τ = 0.93). On a livegpt-4o draw of17

Reproducibility
All code, data, and evaluation harnesses are released. The implementation is in Python
3.10 and runs untrusted LLM-generated code in an isolated subprocess. The full pipeline
reduces to one command:
python eval/run_eval.py --backend openai --direct-gpt --specmind
Mock results are deterministic. Live results are reported with persona temperatures (range
0.1–0.9) fixed inbaldps/agents.pyand the defaultgpt-4omodel.
A AST-level fragment surgery and mutation
The synthesiser and the mutator both operate at the Python AST level. The synthesiser
parses each spec source withast.parse, identifies therequires and ensures FunctionDef
nodes via the standard ast.walk, lifts them as ast.get_source_segment string slices
alongside the module-level helpers, and reassembles arbitrary(r,e )recombinations by string
concatenation followed byast.parsevalidation.
The mutator enumerates the mutation sites of Theorem 1 in walk order. Thek-th
mutant is produced by reparsing the source on each call (so identity of nodes is stable
across mutants) and applying thek-th edit in walk order, thenast.unparse-ing back to
source. Mutants that fail to unparse, or that round-trip identically to the original under
ast.unparse, are dropped. Equivalence (Theorem 2) is checked behaviourally onP by
sandboxed execution rather than syntactically.
B Implementation details
Sandbox.Every spec and implementation runs in an isolated Python subprocess with
a five-second wall-clock timeout. On timeout the batch is retried call-by-call, so a single
non-terminating call cannot poison its neighbours.
Structural probe generator.Disagreement-driven probe proposal is supplemented by
a deterministic generator that, for each example input from the task tests, emits one-edit
structural variants: empty containers, singletons, duplicates, sign flips, zero, and mixed-case
variants for strings. Coverage of canonical edge cases is thereby independent of the LLM
adversary’s stochastic sample.
Caching.The live backend caches one( specs,impls,probes,interview )tuple per task
per process. The random-query-strategy sweep and the ablation grid therefore operate on

identical samples, removing sampling noise from the contrast.
Self-debug retry.If the LLM re-synthesis produces a spec that contradicts an evidence
point, the failing point is fed back as a “previously rejected because...” hint and the LLM
is asked to fix it. The retry is capped at one extra call.
