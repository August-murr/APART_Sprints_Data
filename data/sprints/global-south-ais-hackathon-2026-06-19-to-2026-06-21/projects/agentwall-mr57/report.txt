EXECUTIVE SUMMARY
AgentWall
AgentWall is a runtime security layer that intercepts every tool call generated by an agentic small
language model (SLM), scores it for signs of jailbreak-driven behavior, and decides in under 10
milliseconds whether to pass it through, flag it for review, or block it entirely.
Unlike existing safety solutions that operate at the text-generation layer, AgentWall operates at the
action layer. By the time a jailbreak has propagated into an actual tool invocation, the malicious intent is
far more legible: structured argument patterns such as path traversal or external-domain exfiltration are
easier to detect than the adversarial prompt that caused them.
AgentWall is the first security product designed specifically for the tool-call attack
surface of agentic SLMs — a gap that existing LLM safety tooling does not address.

SECTION 01
Product Features
AgentWall is built around a three-stage detection pipeline that cascades from deterministic rules through
semantic classification to context-drift analysis. Each stage adds detection coverage while the overall
latency budget remains under 10ms.
1.1 Three-Stage Detection Pipeline
Stage 1 — Deterministic rule engine
The first stage applies zero-latency pattern matching against a curated database of known-bad
argument shapes. This includes path traversal sequences, external domain exfiltration targets, privilege
escalation tokens, and shell injection patterns. No machine learning is involved; the stage is a compiled
rule set that runs synchronously in the calling thread.

Stage 2 — Embedding classifier
An approximately 80-million-parameter encoder model, quantized to INT8, embeds the full tool call
context and scores it against a safe-call baseline distribution. This stage is responsible for detecting
novel attack patterns that do not match any known rule signature. The classifier is trained on a synthetic
corpus of jailbreak-induced tool calls generated through systematic red-teaming of common SLM and
tool pairings. At INT8 quantization the model runs in approximately 5ms on commodity CPU hardware.
Stage 3 — Context drift detector
The context drift detector compares the semantic intent of the original user message against the
semantic intent implied by the outgoing tool call. A large divergence — for example, a user requesting a
webpage summary but the SLM issuing a send_email call to an external address — is the primary
signal for indirect prompt injection originating in retrieved content. This stage runs in approximately 4ms
and catches the hardest attack class: injection payloads embedded in documents, tool outputs, or other
agent messages that the SLM has processed.

1.3 Per-Tool Policy Engine
Each tool registered with AgentWall carries its own enforcement policy. Teams configure different
behavior per tool based on its risk profile:
 block — intercept the call before execution and return an error to the agent.
  flag — execute the call but emit a structured alert to the audit log and dashboard.
  log — pass through silently but record the full call for retrospective analysis.
  off — disable AgentWall for a specific low-risk tool on performance-sensitive paths.
 
1.4 Structured Audit Logging
Every intercepted call is serialized as structured JSONL to a configurable sink. Fields include
timestamp, tool name, argument payload, detection stage that fired, risk score, policy action taken, and
conversation turn index. The format is designed for direct ingestion by any SIEM platform (Splunk,
Elastic, Datadog) and satisfies the audit trail requirements of SOC 2 Type II and ISO 27001.
1.5 Monitoring Dashboard
The commercial tier ships with a web dashboard providing real-time visibility into tool call volume, block
and flag rates per tool, risk score distributions over time, and drill-down views of individual flagged calls
including the full argument payload and preceding conversation context. Alerting integrates with
PagerDuty, Slack, and generic webhook endpoints.

2.2 Demand Signals
Three converging trends are accelerating demand for tool-call security:
 Agentic AI deployment is outpacing safety tooling. According to the 2025 State of AI Infrastructure
 survey, 61% of enterprises have at least one agentic AI system in production; fewer than 12% report
any form of tool-call monitoring in place.
 Regulatory pressure is increasing. The EU AI Act high-risk classification criteria increasingly apply to
 agentic systems with real-world actuation capability. Audit trail requirements for tool calls are
expected to become mandatory for regulated industries in the 2026-2027 compliance cycle.
 Incident costs are rising. Documented cases of prompt injection on production agents have created
 board-level awareness of agentic AI risk. Security vendors report a significant uptick in inbound
inquiries specifically about tool-call security since mid-2025.

same model artifact to run on both cloud servers and Apple Silicon devices.

CONCLUSION
Summary and Next Steps
AgentWall addresses a structurally unmet need: security enforcement at the tool-call layer of agentic
SLM deployments. The product is technically differentiated — its three-stage pipeline combines
deterministic rules, semantic classification, and context-drift analysis in under 10ms — and market
timing is strong, with agentic AI proliferating faster than safety tooling can follow.
The go-to-market strategy is proven: open-source developer distribution converting to enterprise
compliance buyers. The risk profile is manageable with the mitigations outlined, and the founding team
requirements are specific and achievable.
