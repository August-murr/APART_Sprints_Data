Closing the Unowned Trust Boundary: Runtime KV-Cache Integrity
Veriﬁcation against Safety-Bypass T ampering
Tianyu Lu ⋅ Independent Researcher Global South AI Safety Hackathon — Asia / T echnical Safety track
Abstract
The KV cache is the dominant stateful component of LLM inference, and safety-critical signals propagate
from aligned weights into its mutable value vectors at every decoding step — yet no production serving
framework veriﬁes the integrity of cached values. Prior work (SCALPEL) [15] exploited this gap to disable a
model’s trained refusal behavior by erasing safety directions from the cache, while keeping every deployed
integrity signal — weight hashes, forward-pass hooks, input/output screening, behavioral spot-checks —
invariant. That work was framed as a systems exploit; here we reframe it as what it actually is: an integrity
gap in runtime model state that the entire compliance-veriﬁcation stack is blind to, and that no layer
of the inference stack claims ownership of. We then close it. We build a sampled runtime KV-cache
integrity check that, at each decoding step, recomputes value vectors from the model’s own weights ( v*
= W_V ⋅x_t) for a random subset of (layer, head, token) and compares them to the cache. The attacker’s
deﬁning stealth property — a bit-identical forward pass — is exactly what makes the recomputation a
reliable ground truth. The detector achieves AUC 0.9996 , empirical FPR = 0 (robust to distribution shift and
batching up to 16), and a sequence-level detection probability of 1.0 even at a 1% per-step sampling
rate, at a measured cost of +5.9% decode latency (≈99% of which is dispatch overhead, eliminable by
kernel fusion to sub-1%). A game-theoretic analysis shows the attacker has no escape: evading per-step
detection by erasing fewer heads collapses attack success from 65% to 5% while remaining caught at the
sequence level.
1. Introduction
Modern LLM serving is built around the key–value (KV) cache: a per-request runtime buﬀer that stores
intermediate Key/Value projections so the model need not recompute attention over the full context at
each step. Frameworks treat this buﬀer as a transparent performance optimization — allocating, evicting,
quantizing, and sharing it with no integrity contract.
But the KV cache is not merely a performance artifact. The model’s learned refusal behavior is mediated by
a low-dimensional direction in representation space [1], and that direction propagates into cached value
vectors through the value projection (v = W_V ⋅x). Safety-critical state therefore migrates from the protected,
attested weight space into a mutable, operator-controlled runtime buﬀer — and the security perimeter
around LLM deployments protects every component except this one. Weight checksums, input ﬁlters,
forward-pass monitoring, and output classiﬁers all leave the KV cache unguarded.
This work makes three contributions:
1. A repositioning (Section 4). The cache-level safety-bypass attack is not a remote exploit and not
a single-framework bug. Its true signiﬁcance is that it defeats the integrity-attestation mechanisms
on which deployment compliance relies, and that no layer of the inference stack — model vendor
or serving framework — claims ownership of cache-content integrity. It is an unowned trust
boundary.
2. A defense (Sections 5–6). A sampled runtime KV-cache integrity check — recompute value vectors
from the model’s weights and compare to the cache — that is the missing attestation layer for this
boundary.
3. A complete characterization (Section 7). Detection (TPR 99.6%, FPR 0, AUC 0.9996), robustness
(survives distribution shift, batching), cost (+5.9% at the saturation operating point), and a game-
theoretic argument that detection evasion forfeits the attack.

2. Background
Refusal directions. Safety-aligned models are trained to refuse harmful requests, and this learned refusal
has a strikingly simple geometry: it is mediated by a small number of directions in the residual stream,
extractable via contrastive activation analysis over harmful vs. harmless prompts [1]. Crucially, this direction
is present in the value projection output that gets written to the cache.
The KV cache as a trust boundary. For an L-layer, H-head model, the cache stores per-head Key/Value
tensors for every past token. These are continuously evicted, quantized, and shared with no safety consid-
eration. The security-relevant observation: the refusal direction enters the cache through v = W_V ⋅x, so
the buﬀer carries the model’s intent to refuse — in a region no deployed veriﬁcation mechanism inspects.
Threat landscape. Recent work has examined KV-cache privacy (prompt reconstruction from cached
tensors) [10] and KV-cache manipulation attacks (trojans and narrative steering via cached state) [11, and
related]. KV-cache–level defenses to date target either conﬁdentiality or input-token relevance — e.g. Ro-
bustKV [5] defends against jailbreaks by evicting low-importance prompt tokens. None verify the integrity
of cached value content — the surface this work concerns.
3. The Attack: What It Exposes
This section summarizes the cache-level safety-bypass attack (SCALPEL) [15] at the level needed to moti-
vate the defense. We describe the mechanism, not a reproduction recipe; attack code is withheld pending
available defenses, consistent with the original responsible-disclosure posture.
3.1 Mechanism
The attack operates in three stages on an open-weight model the operator controls:
• Scan. Extract per-layer refusal directions from a small set of contrastive pairs, and map which atten-
tion heads carry the most safety signal (an Energy/Selectivity decomposition).
• Plan. Select target heads and assign a per-head erasure strength.
• Strike. At every decoding step, project the safety direction out of the newly cached value vectors —
a rank-1 operation. Model weights are never modiﬁed; the forward pass executes its original code
path.
3.2 T wo structural facts that matter for the defense
The iceberg structure. Safety is not concentrated in a few heads. A small “tip” of high-selectivity heads
in the ﬁnal layers carries a large share of refusal energy, but a distributed base across all layers carries the
rest. Erasing only the tip is insuﬃcient — the distributed base sustains refusal. This is why an eﬀective
attack must touch many heads, a fact the defense exploits in Section 7.

Per-step erasure is necessary. A one-shot erasure is undone by attention-mediated feedback: each new
token re-reads refusal signal from un-erased positions and re-injects it via W_V. The attack must therefore
erase at every step. This temporal signature is precisely what makes the attack repeatedly observable to a
per-step detector (Section 6).

The attack is eﬀective and transfers to production serving ( ≈74% attack success on a vLLM deployment,
86% agreement with the reference implementation) [15], and it bypasses representation-level defenses that
weight-modiﬁcation attacks cannot — e.g. it succeeds against Circuit Breakers [3] (cache 49.1% ) where
weight abliteration [1] scores 0%. But its decisive property is invisibility to the standard compliance-

4. Repositioning: The Unowned Trust Boundary
The above was framed, in its original venue, as a systems exploit. That framing is the wrong one, and
correcting it is this work’s conceptual contribution.
4.1 What is actually attacked
The attacked asset is the auditor and the attestation contract , not the memory safety of any serving
framework. Compliance veriﬁcation of a deployed model rests on an enumerable set of integrity signals
(weight hashing, hook enumeration, I/O screening, behavioral spot-checks); the attack holds all of them
invariant while violating safety, because cache content lies outside the attested surface.
4.2 Attacker model
Primary — the Malicious Operator (auditability evasion). This is the load-bearing scenario, and it is a
compliance threat, not an exploitation one. The operator already has legitimate full control of the runtime;
gaining access is not part of the threat. The threat is that the operator maintains a compliant façade —
passing every integrity check a licensor or regulator deploys — while disabling safety for selected requests.
Cache-content modiﬁcation is uniquely suited to this because each obvious alternative is caught by exactly
one layer of the standard defense-in-depth stack (swapping the model → weight checksums; hooking

Secondary (demoted, with an explicit concession) — the Compromised Server. An external attacker
with in-process code execution could inject the same operation. We subordinate this scenario and concede
the point directly: once an attacker has in-process RCE, the threat model largely collapses — such an
attacker could swap weights or replace the model outright, and the marginal value of cache manipulation
is limited to being the path of least resistance within a component-isolation envelope. We claim no stealth
advantage in this scenario and do not present cache erasure as a novel exploitation technique here.
4.3 The responsibility-assignment gap
The decisive systems observation comes from the disclosure outcome. The cache-content integrity gap
was disclosed to ﬁve inference-framework maintainers and ﬁve model vendors. The consistent response
treated cache content integrity as an operational concern rather than a framework-level vulnerability ,
on the grounds that in-process code execution implies full compromise; no CVE or advisory was assigned.
This response is not a refutation — it is the ﬁnding. No layer of the inference stack claims ownership of
KV-cache content integrity:
• Model vendors treat post-deployment runtime state as the serving framework’s responsibility.
• Serving frameworks treat in-process integrity as out of scope (RCE ⇒ full compromise).
• The result is a trust boundary — safety-critical state moving from attested weights into an unattested
runtime buﬀer — that is owned by no one.
The contribution for the systems community is therefore not “framework X has a bug,” but “the inference
stack’s trust model has an unassigned region, and deployed compliance attestation is blind to it.”
4.4 Regulatory grounding (independently veriﬁed)
The compliant-façade threat is precisely the adversary that compliance and licensing regimes are designed
to bind — and current attestation provably misses it.
• EU AI Act, Article 26 (deployer obligations) [11]. Deployers of high-risk systems must take technical
and organisational measures to operate systems in accordance with the provider’s instructions
for use ; high-risk obligations apply from 2 August 2026 . Cache erasure means the deployer is not
operating the system per the provider’s safety design — yet no deployed attestation can establish
this. (This is the correct anchor for the Malicious Operator.)
• EU AI Act, Article 15(5) (cybersecurity) [11]. High-risk systems must be resilient against unautho-
rised third parties altering their use, outputs, or performance, with technical measures against data
poisoning, model poisoning, and model evasion. (Because it targets unauthorised third parties, this
anchors the secondary Compromised-Server case, not the operator case.)
• White House Voluntary Commitments (2023; 15 companies) [12]. Signatories committed to cy-
bersecurity and insider-threat safeguards for unreleased/proprietary model weights , treated as
core intellectual property. This codiﬁes weight integrity as the industry standard — but is silent on
inference-time ephemeral runtime state, which is exactly the gap.
• NIST AI RMF 1.0 (2023) + Generative AI Proﬁle (AI 600-1, 2024) [13]. The framework requires
T esting, Evaluation, Veriﬁcation, and Validation (TEVV) across the lifecycle, and the GenAI Proﬁle
notes that pre-deployment TEVV may be inadequate for deployment-time scenarios. Runtime cache
tampering falls under the proﬁle’s Information Security risk category (integrity attacks on the system)
— and is covered by no existing TEVV procedure we are aware of.
• Model licensing [14]. Meta’s Llama Acceptable Use Policy (Clause 1.h): the compliant-façade de-
ployment violates the license while remaining invisible to the veriﬁcation licensors currently deploy.

5. The Defense: Sampled Runtime KV-Cache Integrity Veriﬁcation
5.1 Core idea
The detection asymmetry is the constructive core. Weight modiﬁcation is caught by weight checksums;
cache erasure evades all weight-level audits but is detectable by recomputation — verifying that cached
value vectors equal what the model’s unmodiﬁed weights would produce:
For sampled (l, h, t): v* = W_V[l,h] . x_t compare to v_cache[l,h,t]
flag tampering if ||v_cache - v*|| / ||v*|| > tau
No production framework implements this check. Our defense builds it as a lightweight, sampled, per-step
monitor.
5.2 Why the attacker’s stealth is the defender’s hook
The attack’s signature property is a bit-identical forward pass (that is what makes it invisible to hook
audits). But that same property means the pre-projection hidden state x_t is untampered — so W_V⋅x_t
recovers the true value vector, and the cache’s deviation from it is the tampering signal, with magnitude ≈
𝛼⋅(v⋅r̂) (the erased refusal component). The property that makes the attack stealthy against existing
defenses is the property that makes it detectable by ours.
5.3 Detector design
Four design choices, each validated empirically (Section 7):
1. Value space, not Key space. Value vectors are the raw projection output and can be compared
element-wise; Key vectors carry rotary position encoding and would require positional alignment ﬁrst.
(Safety signal also resides almost entirely in value space.)
2. fp32 L2-relative distance, not native bit-equality. A naïve “native dtype recompute must match
exactly” test fails: independent recomputation uses a diﬀerent GEMM shape than the model’s fused
projection, and the stored cache is itself non-bit-deterministic across batch size. An fp32 recompute
compared by L2-relative distance over the 128-dim head averages out per-element noise and
yields a stable ﬂoor (~8 ×10⁻⁴), well below the tamper signal.
3. Per-step, new-token-only. Mirroring the attack’s temporal structure: at each decode step the de-
tector checks only the newly generated token’s entry; prompt-token entries are checked once after
preﬁll. No rescanning of past positions (which both costs more and would misread already-erased
state).
4. Sampling. Checking only a random fraction k of the (l,h,t) universe per step trades detection proba-
bility for overhead. The whole story is that k can be tiny.
6. Experimental Setup
Llama-3-8B-Instruct (HF Transformers, fp16), deterministic decoding (seed 42, greedy), single GPU (RTX
PRO 6000). The detector recomputes against the model’s own W_V (GQA head-mapping veriﬁed). Evalua-
tion prompts: 20 HarmBench [2] behaviors (tampered condition, via the real per-step erasure) + 10 benign
prompts (benign condition). The attack’s full-uniform plan targets 196 heads; a targeted plan (iceberg tip)
targets 8.
Scope (locked): HF path only — the defense mechanism is framework-independent and an HF PoC suﬃces;
a vLLM port is future work. Single model — the check is W_V⋅x recomputation, which is model-independent;
multi-model robustness is deferred.

7. Results
7.1 Detection (E1)
Under the real per-step attack, at the detector’s FPR=0 operating threshold ( 𝜏 = 1×10⁻³), the tamper signal
clears the ﬂoor on 99.6% of all (l,h,step) entries — 195.2 of 196 attacked heads detectable at every
token. Preﬁll and decode windows are essentially identical (99.66% vs. 99.61%). This supersedes an
earlier single-position probe that, using a stricter cut on a one-shot erasure, had suggested only ~26%
detectability; under the real per-step attack at the proper operating point, the signal mostly lives in [10⁻³,
10⁻²], above the ﬂoor.
7.2 False positives and robustness (S1–S3)
• ROC (S1): AUC = 0.9996. Empirical FPR = 0 for any 𝜏 ≥ 7.9 ×10⁻⁴; 99% of the tamper signal sits
≥3.2× above the benign ceiling.
• The misses are harmless (S2). The 0.38% of tampered entries below 𝜏 are concentrated where
there was nothing to erase: 76% fall within benign noise, and all have refusal-component fraction
<0.05% — i.e. positions where the attack itself moved the value vector negligibly. No real erasure
hides under the threshold.
• Robust to shift and batching (S3). FPR stays 0 and TPR holds at 99.6% under longer and multilin-
gual benign prompts and at batch size 16; the benign ﬂoor never exceeds 8.2 ×10⁻⁴.

8. Discussion and Limitations
• The detector is statistical, not exact. Native bit-equality does not hold (diﬀerent GEMM shapes;
cache non-determinism across batch). The defense is an fp32 L2-relative test with a calibrated thresh-
old, not a checksum. This is the honest operating model; the ROC (AUC 0.9996) and the structurally-
FPR=0 region ( 𝜏 ≥ 7.9 ×10⁻⁴) are what justify it.
• Threshold margin. The benign ceiling (8.2 ×10⁻⁴) sits close to 𝜏 = 1×10⁻³ (~1.28 × headroom). We
recommend operating at 𝜏 = 1.5–2×10⁻³ for a 2–2.6× safety margin, at ≤0.4% TPR cost — still FPR
= 0.
• Scope. HF Transformers, single model. The vLLM PagedAttention path (where the pre-projection
x_t is not exposed at the execution boundary) and cross-model generalization are deferred. The
mechanism is framework- and model-independent, so we expect these to be engineering, not sci-
ence.
• Quantized cache. A deployment using fp8/int8 KV-cache quantization raises the noise ﬂoor and
would require re-calibrating 𝜏 ; the determinism analysis here assumes fp16 cache.

9. Conclusion
The KV cache carries safety-critical model state into a runtime buﬀer that the entire compliance-veriﬁcation
stack ignores and that no layer of the inference stack claims responsibility for. We reframed the cache-level
safety-bypass attack as the exposure of this unowned trust boundary, and we built the missing attestation
layer: a sampled runtime integrity check that recomputes value vectors from the model’s own weights. It
achieves near-perfect detection (AUC 0.9996, sequence-level P=1.0 at 1% sampling), structurally zero false
positives under shift and batching, single-digit-% cost (sub-1% fused), and leaves the attacker no winning
move.
A closing symmetry makes the cost case concrete: the attack’s overhead is ~99.98% dispatch, and the
defense’s overhead is ~99% dispatch — the same engineering fact governs both, and both collapse to sub-
1% once fused. KV-cache integrity is not expensive to verify. It has simply never been veriﬁed. Runtime
cache integrity should be a standard component of trusted LLM serving, attested alongside model
weights.
Responsible Disclosure
The underlying attack surface was disclosed to ﬁve inference-framework maintainers and ﬁve model ven-
dors prior to publication of the original work; attack code is withheld pending available defenses. This report
describes attack mechanism (already public) but not a reproduction recipe, and contributes a defense. The
work was conducted under the hackathon’s responsible-disclosure policy; no novel attack capability is
released.
