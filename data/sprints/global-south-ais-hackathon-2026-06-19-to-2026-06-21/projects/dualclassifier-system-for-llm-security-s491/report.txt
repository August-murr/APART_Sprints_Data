ABSTRACT
Prompt injection remains one of the most practical threats to LLM-
based agents, yet most detectors require retraining whenever a
new attack pattern or a new language appears. This paper presents
MnM (Monitor and Mitigate), a dual-layer detection system that
replaces gradient-based training with retrieval over a vector data-
base. Layer 1 classifies the incoming prompt by running 𝑘-nearest-
neighbor retrieval over a database of labeled prompt chunks. Layer 2
classifies the model’s reasoning stream as it is produced, using the
same retrieval pipeline against a separate database of compromised
and clean reasoning patterns. Both layers share one multilingual
embedding model (qwen3-embedding-8b, 4096-d) and one chunk-
ing model (mistral-nemo), and their verdicts are fused with a log-
ical OR. We evaluate MnM on 200 English prompts (Gandalf Ig-
nore Instructions + ShareGPT) and 200 Hindi/Hinglish prompts,
with the vector databases built from English data only. On Eng-
lish, the best operating point ( 𝑘=4, 𝜃 =0.7) reaches 84.5% combined
accuracy and 0.86 F1 with 99% recall. On Hindi, where no target-
language data exists in the database, the best point ( 𝑘=5, 𝜃 =0.5)
reaches 77.5% combined accuracy and 0.78 F1. When a small batch
of Hindi reference embeddings (10% of the evaluation set) is seeded
into the database, the prompt lane accuracy rises from 63.0% to
71.1% and combined F1 rises from 0.78 to 0.79, showing that the
retrieval-based architecture can close the cross-lingual gap with-
out retraining.

1 INTRODUCTION
Large language models are increasingly deployed as autonomous
agents that browse the web, execute code, and invoke external
tools on behalf of users. This agentic setting introduces a quali-
tatively new attack surface: prompt injection, in which adversarial
instructions embedded in the environment (a malicious webpage,
a crafted document, a poisoned API response) redirect the agent
away from its original task and toward goals chosen by the at-
tacker [ 3, 4]. Unlike jailbreaks that target the model at inference
time through the user turn, prompt injection exploits the agent’s
trusted perception of its environment, making it difficult to defend
against at the input level alone.
Recent empirical work has established that the threat is not con-
fined to English-language deployments. Burbano et al. [ 2] demon-
strate that indirect prompt injection can reliably hijack embodied
agents across English, Chinese, Spanish, and Spanglish, revealing
that multilingual capability, one of the most valued properties of
modern LLMs, doubles as an attack amplifier. At the architectural
level, Guo et al. [5] identify instruction-hierarchy robustness as an
open problem: agents trained to follow user instructions do not
reliably distinguish between legitimate principal instructions and
injected adversarial ones, especially when the injection is phrased
in an out-of-distribution style for the hierarchy.
Existing detection approaches address prompt injection primar-
ily through input classification or reasoning probes, but share a
common limitation: adapting to a new attack pattern or a new lan-
guage requires retraining or fine-tuning the detector itself [ 6, 7, 9].
This rigidity is costly in the multilingual agentic setting, where at-
tack payloads transfer across languages [ 2] far faster than labeled
defense data can be collected. Additionally, any approach that com-
mits to a decision before generation begins cannot catch an injec-
tion that is syntactically benign at the prompt level but succeeds
by gradually steering the model’s chain-of-thought toward a com-
promised goal.
We proposeMnM (Monitor and Mitigate), a dual-layer detection
system designed to address both failure modes without gradient-
based training. The prompt classifier (Layer 1) operates on the in-
coming prompt: it uses a lightweight language model to extract
semantically meaningful chunks, embeds each chunk with a high-
dimensional multilingual embedding model, and issues a label via
𝑘-nearest-neighbor vote against a vector database of known ma-
licious and benign examples. Because detection knowledge lives
directly in embedding space, updates are immediate: a small set of
newly labeled examples for an unseen attack pattern or a new lan-
guage can be inserted into the database with no retraining cycle.
The classifier bootstraps from existing injection datasets without
requiring manual annotation of model behavior.
The behavioral classifier (Layer 2) activates at generation time.
As the LLM streams its chain-of-thought, MnM chunks the reason-
ing, embeds each chunk, and compares it against a vector database
of known compromised and clean reasoning patterns. A streaming
gate aggregates per-chunk scores and issues an early-stop signal

the moment the reasoning drifts toward injected behavior, before
the model has produced any harmful output or tool call. Both lay-

free philosophy: the behavioral database is built from generated
traces, not from human-annotated reasoning steps. Together, they
provide two independent detection signals, one at the instruction
boundary and one inside the reasoning process, evaluated here on
English and Hindi prompts. This extends the multilingual attack
surface documented by Burbano et al. [ 2] to the detector side.
2 STATE OF THE ART
Benchmarking and threat taxonomy. AgentDojo [3] is the stan-
dard dynamic benchmark for evaluating prompt injection attacks
and defenses in LLM agent pipelines. It provides a suite of realis-
tic tasks across web, file, and calendar environments, and is used
in this work to situate our threat model. Ferrag et al. [ 4] extend
the taxonomy beyond classic prompt injection to protocol-level
exploits in multi-agent workflows, establishing that the attack sur-
face grows substantially as agents compose and delegate to one
another.
Multilingual and agentic attack surface. Burbano et al. [ 2] show
that indirect prompt injection transfers across four languages in
embodied agent settings, with success rates that do not degrade
significantly in non-English targets. This motivates our multilin-
gual evaluation: a detector that only generalizes to English pro-
vides false assurance in the deployment settings that are already
under attack. Guo et al. [ 5] frame the underlying failure as an
instruction-hierarchy problem, where agents cannot reliably rank
the authority of instructions arriving from different principals, and
propose a challenge dataset to measure robustness. MnM addresses
a complementary gap: rather than enforcing hierarchy at the pol-
icy level, it detects when the model’s own reasoning has already
been captured by an injected goal.
Input-level detection. Srinivasan et al. [ 8] analyze prompt injec-
tion detection across Indian multilingual LLMs, finding that cross-
lingual transfer in detectors lags behind transfer in attacker pay-
loads, a gap MnM is designed to close by operating on embed-
ding space rather than token-level heuristics. Sato et al. [6] demon-
strate that in-context exemplars of injected prompts meaningfully
improve detection without fine-tuning, establishing a strong zero-
shot baseline. Yu et al. [ 9] apply fuzzing to generate adversarial
prompt variants and evaluate detector robustness, providing a method-
ology for stress-testing defenses beyond fixed benchmark sets.
Reasoning-aware and RAG-aware detection. Shi et al. [7] propose
Meticulous Thought Defender, which uses fine-grained chain-of-
thought analysis to identify injection signals in model reasoning.
MnM differs in that it operates online during the streaming genera-
tion rather than post-hoc, enabling early stopping before harmful
output is produced. Al Masoud et al. [ 1] address a related threat
in retrieval-augmented generation pipelines: single-turn prompt-
leaking attacks that extract system context through crafted queries.
SD-RAG’s selective-disclosure framing informs our understanding
of what a compromised reasoning trajectory looks like when the
model is manipulated into revealing or acting on injected content.
3 APPROACH
The design of MnM follows from two practical constraints. The
detector has to keep up with new attack patterns and new tar-
get languages without going through a retraining cycle, because
the multilingual attack surface documented in the literature moves
faster than labeled defense data can be collected. Additionally, the
detector cannot commit to a verdict before the model has begun
to reason, because a non-trivial fraction of injections look benign
at the prompt level and only reveal themselves once the model is
several steps into its chain-of-thought. These two constraints point
toward a retrieval-based architecture rather than a fine-tuned clas-
sifier. If the detection knowledge lives in a vector database, then
adding a new attack family or a new language reduces to insert-
ing a small batch of labeled examples, with no gradient updates
required. MnM applies this idea twice, with two independent clas-
sifiers that share embedding infrastructure but operate on different
signals. The first runs on the incoming prompt before generation
begins. The second runs on the model’s reasoning stream as it is
produced. The two verdicts are combined at the end into a single
alarm. Figure 1 shows the overall architecture.
Figure 1: MnM architecture. The input prompt is processed
by both the Behavior Model (Layer 2, top) and the Classifier
Model (Layer 1, bottom). Both lanes share the same chunk-
ing model (Mixtral Nemo) and embedding model (Qwen 3
Embedding), and retrieve from a shared vector database. The
Behavior Model additionally generates a reasoning trace
through Qwen 3 30B before chunking.
Layer 1: Prompt Classifier. The first layer, the prompt classifier ,
operates on the user prompt before the agent begins to act on it.
The prompt is first segmented by a lightweight chunking model
(mistral-nemo). The chunker returns a small set of semantically co-
herent spans together with a tag describing what kind of content
each span carries and a salience score that reflects how relevant
the span is for an injection decision. Chunking is performed by a
separate small model rather than inside the classifier itself, because

the goal at this stage is to isolate the parts of the prompt that ac-
tually carry instructional intent before any embedding cost is paid
on filler text.
Each chunk is then embedded using a high-dimensional multi-
lingual embedding model (qwen3-embedding-8b). The embedding
of every chunk is matched against a vector database of previously
labeled chunks using cosine similarity. The database is hosted in
PostgreSQL with the pgvector extension, and retrieval is performed
in two stages. The first stage uses a binary-quantized index to fetch
a candidate set quickly. The second stage reranks the candidates
using exact cosine distance. This design keeps retrieval latency
bounded as the database grows, which matters because the data-
base is expected to expand over time as new attack examples are
added.
Once the 𝑘 nearest neighbors for a chunk are retrieved, the
chunk is labeled by majority among those neighbors. A chunk is
treated as malicious when the fraction of its neighbors carrying
the malicious label exceeds a configurable threshold. After every
chunk in the prompt has been labeled, the prompt itself is labeled
by a strict majority vote across the chunks. Both the neighborhood
size 𝑘 and the per-chunk threshold are tunable parameters of the
system, and concrete values are deferred to the Evaluation section.
Because the detection knowledge lives in the database rather
than in model weights, the detector adapts cheaply. If a new attack
family appears, a small batch of labeled examples can be embedded
and inserted, and the detector starts catching the new family from
that point onward without retraining. The same holds for new tar-
get languages, because the embedding model is multilingual and
aligns semantically similar text across languages into nearby re-
gions of the embedding space.
Layer 2: Behavioral Classifier. The second layer, the behavioral
classifier, operates on the model’s reasoning stream rather than on
the prompt. When the agent begins to process a prompt, MnM col-
lects the reasoning text emitted by the model (the reasoning field
of the streaming response from a reasoning-capable LLM, qwen3-
30b-a3b-thinking-2507 in our implementation) and feeds it into the
same chunk-embed-retrieve pipeline used in Layer 1. The chun-
ker is the same small model used for the prompt, and the embed-
ding model is the same multilingual encoder. The vector database,
however, is different. It stores fingerprints of reasoning patterns
rather than of prompts, with each entry labeled as either injection
or clean.
This second layer exists because input classification on its own is
not sufficient. An injection that is phrased benignly at the prompt
level can pass Layer 1 and only reveal itself in the way the model
begins to reason about the task. By comparing the live reasoning
against a database of known compromised and clean reasoning pat-
terns, the behavioral classifier provides a second independent sig-
nal that captures this class of attacks. The classifier produces a per-
chunk label and an overall verdict using the same kNN majority
logic as Layer 1.
Because the classifier produces a signal per reasoning chunk, the
architecture is compatible with streaming use, where the next per-
chunk signal becomes available as soon as the next chunk arrives.
This property is what makes an early-stop gate possible: a stream-
ing gate that aggregates per-chunk signals as they are produced
can interrupt generation before the model emits a final response
or a tool call. The current evaluation operates on full reasoning
traces, so the details of the gate aggregation rule are not fixed here.
The gate is treated as a downstream consumer of the per-chunk
signal, and its operating point is left to future calibration work.
Vector Database and Labeling. Both layers share the same back-
ing infrastructure and the same embedding model, but their databases
are populated from different sources. The Layer 1 database is built
by chunking and embedding prompts from the Malicious Prompt
Detection Dataset (MPDD), with each chunk inheriting the prompt-
level label. The Layer 2 database is built by sampling prompts from
MPDD, running them through the same reasoning model used at
inference time, chunking the resulting traces, and embedding each
chunk. Labels are inherited from the input prompt. A reasoning
trace produced from a malicious prompt is added to the injection
bank, and a trace produced from a benign prompt is added to the
clean bank.
This input-based labeling is convenient because it does not re-
quire any per-trace annotation, but it is slightly noisy. A model that
resists an injection still produces safe reasoning, and that reason-
ing is added to the injection bank if it originated from a malicious
prompt. The Discussion section returns to this point and identifies
outcome-based labeling, where a judge model verifies whether the
injection actually succeeded, as the natural next step. The current
databases are sufficient to support the evaluation reported in the
rest of the paper, but the labeling strategy is a known source of
measurement noise.
Hyperparameters and Fusion. MnM exposes two operating-point
parameters that apply to both layers identically. The first is the
neighborhood size 𝑘, which controls how many examples each
chunk is compared against during retrieval. The second is the per-
chunk threshold, which controls how much agreement among those
neighbors is required before a chunk is flagged. Concrete values for
both parameters are deferred to the Evaluation section, where they
are swept across a held-out set. The per-chunk threshold in partic-
ular embeds a precision-recall tradeoff directly into the system. A
high threshold produces few flagged chunks but very high preci-
sion per flag. A lower threshold catches more borderline cases at
the cost of more false positives. Calibrating the threshold against
the deployment setting is therefore part of the evaluation rather
than a fixed design decision.
The two lane verdicts are fused with a logical OR. The combined
detector raises an alarm if either the prompt classifier or the behav-
ioral classifier reports an injection. This choice is conservative on
purpose. The two layers detect different failure modes, and an at-
tack that is caught by either layer is an attack that the system can
block. In the evaluation harness used in this work, both lanes al-
ways run on every prompt, even when the first lane has already
raised an alarm, because the harness needs to measure each sig-
nal independently before combining them. In a deployed setting
it would be reasonable to short-circuit on a Layer 1 hit, since the
agent has not begun to reason yet, but the harness reported here
treats the two signals as independent measurements.

4 EV ALUATION
Datasets. The vector databases that back both layers are built
from the Malicious Prompt Detection Dataset (MPDD). The Layer 1
database contains 89 846 chunk embeddings derived from MPDD
prompts. The Layer 2 database contains 28 060 chunk embeddings
derived from reasoning traces that were generated by running MPDD
prompts through the same reasoning model used at inference time
(qwen3-30b-a3b-thinking).
Because both databases are built from MPDD, evaluating on
MPDD would test on training data for the prompt lane. All eval-
uation is therefore conducted on held-out datasets that were never
used to populate the databases.
English. We construct a balanced test set of 200 prompts: 100 in-
jection prompts drawn from the Gandalf Ignore Instructions dataset (Lak-
era, MIT license), a collection of human-written instruction-override
attacks, and 100 benign prompts drawn from the ShareGPT conver-
sational corpus.
Hindi/Hinglish (zero-shot). We use 200 prompts (100 malicious,
100 benign) from the Hindi and Hinglish Prompts dataset, equally
split between Hindi and Hinglish. This is a zero-shot cross-lingual
evaluation: the vector databases contain only English data, and no
Hindi or Hinglish examples are present at retrieval time.
Hindi/Hinglish (low-label seeding). To test whether the retrieval-
based architecture can close the cross-lingual gap with minimal
labeled data, we run a second Hindi evaluation after seeding the
shared vector database tables with a small batch of Hindi reference
embeddings. These reference embeddings correspond to 10% of the
Hindi evaluation set (approximately 18 prompts), chunked and em-
bedded through the same pipeline, then inserted into the existing
English tables with a +10 000 000 primary-key offset to avoid colli-
sions. This experiment uses 180 prompts (90 malicious, 90 benign).
Models. Three models form the inference pipeline.mistral-nemo
segments prompts and reasoning traces into semantically coherent
chunks. qwen3-embedding-8b embeds each chunk into a 4096-
dimensional vector. qwen3-30b-a3b-thinking generates the rea-
soning trace that the behavioral layer classifies. All models are ac-
cessed through OpenRouter, and all calls use temperature 0.
Infrastructure. Embeddings are stored and retrieved from Post-
greSQL 17 with pgvector 0.8.2. Retrieval uses a two-stage pipeline:
binary-quantized Hamming HNSW to fetch 64 candidates, followed
by exact cosine reranking to return the top- 𝑘.
Hyperparameter sweep. The system exposes two parameters: the
neighborhood size 𝑘 and the per-chunk threshold 𝜃 (the fraction of
a chunk’s 𝑘 neighbors that must be injection-labeled for the chunk
to be flagged). We sweep 𝑘 ∈ { 1, . . . , 10} and 𝜃 ∈ { 0.1, 0.2, . . . , 1.0},
yielding 100 operating points per evaluation setting. For 𝑘 values
up to the original retrieval depth, the sweep re-uses stored neigh-
bor lists (offline, no database access). For larger 𝑘, the sweep re-
queries pgvector with the stored embeddings.
Metrics. For each operating point we report accuracy, F1, preci-
sion, and recall for the prompt classifier (class), the behavioral clas-
sifier (behavior), and the combined OR-fused verdict. Confusion
matrices are reported at the best operating point for each evalua-
tion setting.

6 DISCUSSION
The behavioral layer of MnM targets a failure mode that input clas-
sifiers cannot catch: an injection that looks benign at the prompt
level but succeeds by gradually steering the model’s reasoning. By
operating on the reasoning stream directly, MnM can detect this
drift and issue an early-stop signal before the model completes
its generation. This property is architecturally impossible for any
post-hoc or input-only system.
The gate design embeds a precision-recall tradeoff as a first-class
hyperparameter. A strict threshold catches high-confidence injec-
tions with few false positives, while a lenient threshold catches
lower-confidence injections at the cost of higher false-positive rates.
The evaluation results show that the operating point matters more
than the underlying embedding quality: moving from𝜃 =0.5 to 𝜃 =0.7
on English raises combined accuracy from 73.0% to 84.5% with the
same embedding model and the same database. Calibrating this
tradeoff on a held-out set is therefore a necessary step for any de-
ployment.
The multilingual evaluation surfaces a distributional challenge
that is specific to the behavioral approach: if the reasoning patterns
in the vector database are drawn from English traces only, cross-
lingual generalization depends entirely on the embedding model’s
multilingual alignment. Our Hindi evaluation provides an initial
signal on this, with the behavioral lane reaching 79.0% accuracy in
the zero-shot setting. However, the prompt lane struggles at 63.0%
accuracy under the same conditions. The low-label seeding exper-
iment addresses this directly. By adding a small batch of Hindi ref-
erence embeddings (approximately 10% of the evaluation set) into
the shared database, the prompt lane improves by over 8 percent-
age points in accuracy and its F1 rises from 0.53 to 0.70. This sup-
ports the practical claim of the retrieval-based architecture: new
language support can be bootstrapped from a small set of labeled
examples rather than requiring a full retraining cycle.
At the same time, the seeding experiment introduces a nuance
to the “training-free” claim. While MnM does not use gradient-
based training, it does require curated labeled data in the vector
database. The distinction is practical rather than theoretical: adding
18 labeled Hindi prompts to the database is far cheaper than fine-
tuning an embedding model or retraining a classifier, but it is not
zero effort. For languages or attack families where even a small
labeled dataset is unavailable, the system falls back to whatever
cross-lingual transfer the embedding model provides on its own.
A separate limitation is the labeling strategy. Traces are labeled
by input (malicious prompt ⇒ injection bank, benign prompt ⇒
clean bank). This is slightly noisy because a model that resists an
injection produces safe reasoning despite originating from a mali-
cious prompt. Outcome-based labels, using a judge to verify whether
the injection actually succeeded, would produce a cleaner bank and
are a natural next step.
Broader coverage remains necessary. The evaluation covers Eng-
lish and Hindi, but the multilingual attack surface documented
by Burbano et al. [ 2] spans at least four language families. Extend-
ing the evaluation to the full set of languages identified in that
work, including Chinese and Spanish, would strengthen the gener-
alization claims.
7 CONCLUSION
We presented MnM, a dual-layer system for real-time detection of
prompt injection in LLM agents. The main contribution is a behav-
ioral classifier that monitors the model’s reasoning stream as it is
generated, compares chunks against a vector database of compro-
mised and clean reasoning patterns, and can trigger an early-stop
gate before a harmful response or tool call is emitted. The system
requires no gradient-based training and has been evaluated on Eng-
lish and Hindi prompts, reaching 84.5% combined accuracy on Eng-
lish and 77.5% on Hindi in a zero-shot cross-lingual setting.
The low-label seeding experiment shows that adding a small
batch of target-language reference embeddings to the database can
close part of the cross-lingual performance gap, especially for the
prompt lane, without any retraining. This supports the core design
hypothesis: that encoding detection knowledge in a vector data-
base rather than in model weights makes the system easier to ex-
tend to new languages and attack families.
MnM addresses the multilingual attack surface documented by Bur-
bano et al. [2] from the detector side, and the instruction-hierarchy
gap identified by Guo et al. [ 5] from the behavioral monitoring
angle. Open problems include calibrating the streaming gate on
held-out data, scaling the reasoning bank, improving the labeling
strategy with outcome-based judges, and extending the evaluation
to more languages.
